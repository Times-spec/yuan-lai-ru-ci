Harness：铁面无私的 AI 监考官

给考试配一个铁面无私的监考官
👀 日常场景

开发者"给新出的开源模型跑个分，看看是不是吹牛"——但同样的卷子，换个问法分数就变。怎么保证你跑的分和官方公布的是同一个"分"？这就需要 Harness 来统一"执考"。

原理：它是怎么运作的

💡 统一 prompt、few-shot 数、任务版本和打分指标的"执考框架"，让不同模型的分数站在同一起跑线上。

先看全过程

  1. 选任务：mmlu、gsm8k 等
  2. harness 按统一模板发卷
  3. 固定 few-shot 数和 prompt
  4. 收集所有模型输出
  5. 按同一套指标打分
  6. 分数可比、可复现、可进 CI

有了考卷，还需要铁面无私的监考官。LLM 评测有个恼人特性：prompt 写法稍变，分数就崩。同样测 MMLU，题目前加"请回答："和不加能差好几个点；few-shot 给 5 个和给 0 个更是天壤之别——A 模型 75 分、B 模型 78 分，姿势不同根本没法比。

Harness 就是来统一姿势的：EleutherAI 的 lm-evaluation-harness 把 prompt 模板、few-shot 数、任务版本、打分指标全部标准化，一行命令跑分，任何模型都站在同一起跑线上。它内置 300+ 学术任务，支持 HuggingFace、vLLM、OpenAI API 等后端，是 HF Open LLM Leaderboard 背后的标准工具。

在逻辑链上，Harness 承接 Benchmark 的"有卷无官"：考卷解决"考什么"，它解决"怎么考才公平"。注意边界：它测的是学术基准上的"裸能力"，RAG、Agent 行为需要另一类 harness（如 SWE-bench 的执行沙箱）。

开发者：应该如何接入

  • lm-evaluation-harness：EleutherAI 出品，pip install lm-eval
  • Open LLM Leaderboard：Hugging Face 官方排行榜背后的标准
  • 评测进 CI：接入 CI，每次更新模型自动跑回归
  1. 选任务：mmlu、gsm8k…
  2. harness 统一发卷
  3. 固定 few-shot 数和 prompt
  4. 收集模型输出
  5. 按同一指标打分
  6. 结果可复现、可发表
