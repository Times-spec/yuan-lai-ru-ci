Tauri/Electron：用网页技术做桌面 App

用网页技术，做桌面应用
👀 日常场景

VS Code 界面像网页，却能读写本地文件——它是 Web 技术做的桌面应用。而 1Password 安装包只有十几 MB。同样“网页做桌面”，一个走 Electron，一个走 Tauri，体积差出一个数量级。

原理：它是怎么运作的

💡 Electron 是“自带整个 Chromium 浏览器”：体验一致但包大；Tauri 是“借用系统自带的浏览器内核”：包小但依赖系统环境。

先看全过程

  1. 想复用 Web 技术栈开发桌面应用
  2. Electron：打包整个浏览器
  3. 前端跑在自带浏览器里，体验处处一致
  4. 代价：每个应用都背着上百 MB 的浏览器
  5. Tauri：改用系统自带的 WebView 渲染
  6. Rust 写后端，安装包只剩几 MB

Electron 的思路是“大力出奇迹”：把 Chromium（渲染网页）和 Node.js（读写文件、调系统 API）打包进每一个应用。前端开发者用熟悉的 HTML/CSS/JS 就能做出 VS Code、Slack、Discord 这样的桌面软件，且 Windows/macOS/Linux 渲染完全一致。但代价是每个应用都自带一个浏览器：安装包动辄上百 MB，内存占用也高。

Tauri 走了另一条路：不打包浏览器，直接调用操作系统自带的网页渲染内核（Windows 的 WebView2、macOS 的 WebKit），后端用 Rust 写（替代 Node.js 的角色，负责文件、系统调用）。1Password 8 就是这么做的，安装包只有十几 MB，内存占用也小一个量级。

Trade-off 很清晰：Electron 生态成熟、行为一致，适合复杂应用和快速交付；Tauri 轻量、安全模型更严格（默认能力受限），适合对体积敏感的新项目，代价是 Rust 学习成本，以及不同系统 WebView 版本差异可能带来的样式小坑。没有银弹，只有取舍。

开发者：应该如何接入

  • Electron：打包 Chromium + Node，生态最成熟
  • Tauri 2.0：系统 WebView + Rust 后端，轻量还支持移动端
  • PWA / Web 应用：干脆不做桌面端，浏览器即应用
  1. 评估：需要文件系统/托盘/全局快捷键等系统能力吗
  2. Electron：electron-forge 脚手架起项目，前端照常用
  3. 主进程（Node）负责系统调用，渲染进程负责界面
  4. Tauri：npm create tauri-app 起项目，学基础 Rust
  5. Rust 端用 #[tauri::command] 暴露能力给前端调用
  6. 打包：注意签名和自动更新通道（electron-updater / tauri updater）
