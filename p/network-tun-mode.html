TUN 模式：接管所有流量的虚拟网卡

在系统里插上一条虚拟网线
👀 日常场景

有人发现：不开 TUN，浏览器能上网，但游戏客户端、终端里的命令行工具就是不行；一把 TUN 打开，所有软件突然都“全局生效”了。TUN 到底施了什么魔法？

原理：它是怎么运作的

💡 TUN 在系统里创建一张虚拟网卡，把 IP 数据包直接导进来处理；系统代理只是“贴告示”，TUN 是“修新路”。

先看全过程

  1. 电脑上的应用发起网络连接
  2. 系统路由把数据包导入虚拟网卡
  3. Clash 收到原始 IP 数据包
  4. 按规则决定直连还是代理
  5. 直连：直接发往目标
  6. 代理：封装后转发给节点

先分清两个维度：出站模式（规则/全局/直连）回答“流量出去走哪条路”；接管方式（系统代理/TUN）回答“流量怎么被抓到 Clash 手里”。

系统代理像在系统公告栏贴告示：“要走代理的应用请来这个入口”。愿意看告示的（浏览器、多数桌面软件）会走；不看的（很多游戏、命令行工具、后台服务）直接无视，该怎么连还怎么连。它的优点是简单、好关，缺点是覆盖不全。

TUN 则是在系统里凭空插了一条“虚拟网线”（虚拟网卡，如 tun0）：配合系统路由，所有 IP 数据包先被导进来，再由 Clash 按规则处理。这是网络层的接管，不挑应用——UDP、DNS、QUIC 都能处理，不读系统代理的软件也跑不掉。这就是“开了 TUN 才全局生效”的原因：之前那些软件根本没看公告栏。

代价也有：需要管理员/VPN 权限；默认可能隔离局域网（打印机、NAS 突然连不上，要加 bypass）；和其它 VPN/加速器同时开会打架；DNS 最好配合 Fake-IP。所以推荐组合是：日常开 TUN + 规则模式，排查问题时先关 TUN 复测。

要不要开 TUN

  • 开 TUN：虚拟网卡接管所有流量，游戏、终端、后台服务全生效
  • 不开，用系统代理：只在系统设置里“贴告示”，简单好关
  • 按需切换：日常开 TUN，排查问题时先关掉复测
  1. 先判断：你的需求里有没有“不读系统代理”的软件（游戏、命令行工具）？有→开 TUN
  2. 开 TUN 需要管理员/VPN 权限，手机上要点允许
  3. 把局域网段加进 bypass，不然打印机、NAS 会失联
  4. DNS 配合 Fake-IP，不然分流可能不准
  5. 出问题先关 TUN 复测：好了就是 TUN 的锅，再细查
  6. 别和别的 VPN/加速器同时开，会打架
