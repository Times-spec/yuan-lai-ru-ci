回到顶部

滑得太深，一键回到开头
👀 日常场景

看一篇超长文章滑到底，右下角悄悄冒出一个“↑”按钮，点一下页面丝滑地滚回开头。你不用狂按 Home 键，也不用把滚轮搓出火星子——长页面、商品详情、评论区，几乎人人都有它。

原理：它是怎么运作的

💡 监听滚动位置，超过阈值显示按钮，点击用 scrollTo({behavior:'smooth'}) 平滑滚回顶部。

先看全过程

  1. 监听页面滚动事件
  2. 滚动超过阈值显示按钮
  3. 点击按钮触发回滚
  4. 平滑滚动动画执行
  5. 到达顶部后隐藏按钮
  6. 滚动监听做节流优化

别看它简单，体验细节不少。实现分两步：显隐和滚动。显隐靠监听 scroll 事件：当 window.scrollY 超过阈值（比如 400px）就显示按钮，滚回去就隐藏。但 scroll 事件触发极其频繁（滚一下能触发几十次），直接在里面操作 DOM 会掉帧，所以要用节流（throttle，限制每 100ms 最多执行一次）或 requestAnimationFrame。滚动用 window.scrollTo({top: 0, behavior: 'smooth'})，浏览器原生支持平滑滚动动画，不用自己写缓动函数；或者直接给 html 加 scroll-behavior: smooth，一行 CSS 全站生效。容易踩的坑是“滚动容器”：如果页面是内部 div 在滚（比如弹窗里的长列表），监听 window.scroll 就永远触发不了，得监听那个 div 的 scroll。无障碍也别忘：按钮加 aria-label="回到顶部"，让读屏软件能读出来。移动端还有个隐藏福利：iOS 点状态栏就能回顶，那是系统级的，不用你写。

网站是怎么做到的

  • scroll 监听：时刻量体温：监听页面的滚动事件，window.scrollY 超过阈值（比如 400px）就显示按钮，滚回去就隐藏。
  • 节流：别每滚一下就折腾：scroll 事件触发极其频繁，滚一下能触发几十次。用节流限制每 100ms 最多执行一次，否则页面掉帧。
  • scrollTo smooth：原生丝滑：window.scrollTo({top:0, behavior:'smooth'})，浏览器自带平滑滚动动画，不用自己写缓动函数。
  • 滚动容器判定：到底谁在滚：如果页面是内部 div 在滚（比如弹窗里的长列表），监听 window.scroll 永远触发不了，得监听那个 div。
  1. 你往下刷长页面，scroll 事件不断触发（被节流成 100ms 一次）
  2. 滚动距离超过 400px 阈值，右下角“↑”按钮淡入
  3. 你点击按钮，调用 scrollTo 平滑滚回顶部
  4. 滚动动画执行，页面丝滑上升
  5. 到达顶部，按钮自动隐藏，功成身退
