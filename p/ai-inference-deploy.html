推理部署：让模型跑起来

权重会思考了，怎么把它端上桌
👀 日常场景

"本地跑大模型""API 太贵了自己部署"——同样一个 Qwen，有人在笔记本上跟它聊天，有人用它扛住每秒上千次请求。中间差的不是模型，而是真正的推理部署这门手艺。

原理：它是怎么运作的

💡 权重+逐 token 解码就是推理；量化省显存、PagedAttention 提吞吐——部署是另一门手艺。

先看全过程

  1. 加载训练好的权重
  2. 用户 prompt 进来
  3. 逐 token 自回归解码
  4. KV 缓存避免重复计算
  5. 多请求拼成批次一起算
  6. 流式把字一个个吐出来

训练是"烧钱学知识"，推理是"用知识答题"：加载权重，输入 prompt，模型逐个 token 往外"挤"答案——每生成一个词，都要把整个大模型算一遍。这就是为什么大模型回答是"流式吐字"而不是瞬间全文：它真的是一个词一个词想出来的。

部署的核心矛盾是显存：一千亿参数、每个 2 字节（FP16），光权重就要 200GB 显存。两招破局：量化——把权重精度从 16 位降到 8 位甚至 4 位，显存砍半再砍半，精度损失可控；PagedAttention（vLLM 的核心）——像操作系统管理内存页一样管理 KV 缓存，加上连续批处理，把吞吐榨干。

在逻辑链上，推理部署承接"模型训好了"：预训练/SFT/RLHF 产出的只是一堆 .bin 权重文件，怎么把它变成 7×24 稳定、低延迟、扛并发的服务，是另一门手艺。Ollama 让个人一键本地跑，vLLM 让公司扛住生产流量。

开发者：应该如何接入

  • Ollama：ollama run qwen3，一行命令本地跑
  • vLLM：vllm serve 起 OpenAI 兼容 API
  • llama.cpp / TGI：llama.cpp / HuggingFace TGI
  1. 拿到训练好的权重文件
  2. 选精度：FP16 直接跑，或量化到 INT8/4
  3. 加载进显存，建 KV 缓存
  4. 用户 prompt 进来，分词
  5. 逐 token 自回归解码
  6. 流式输出，多个请求拼批处理
