RAG：给大模型外挂知识库

给大模型外挂一个知识库
👀 日常场景

"让 AI 回答公司内部文档""AI 客服引用知识库回答"——模型训练时没见过你们公司的规章制度，却能对答如流。知识不是长在权重里的，而是现场"翻书"翻出来的，这套机制就叫 RAG。

原理：它是怎么运作的

💡 先检索相关文档片段、拼进 prompt 再生成——换文档即换知识，不用重训，答案可引用可审计。

先看全过程

  1. 文档切块
  2. 转 embedding 存向量库
  3. 问题转向量
  4. 检索最相关的片段
  5. 片段拼进 prompt
  6. 基于片段生成，附引用

预训练留下两个坑，其中之一是"知识冻结"：模型只知道训练截止日之前的事，更不懂你们公司的内部文档。重训一次几千万美元，就为了更新知识？RAG 说：别重训，给模型外挂一个知识库。

流程像开卷考试：先把文档切成块，转成向量存进向量库；用户一提问，把问题也转成向量，去库里捞出最相关的几块，拼进 prompt 再让模型生成。因为答案是"看着资料说的"，还可以要求它标注引用来源，可审计、可追溯。换一批文档，模型的"知识"就换了——知识更新从"重新训练"降级成"换个文件"。

在逻辑链上，RAG 承接预训练的"知识冻结"和"不懂私有数据"：它是"外挂知识"方案，与之相对的是 SFT/微调"内化知识"。分工口诀：行为用微调定，知识用 RAG 补。但别指望它根治幻觉——检索错了，模型会一本正经地引用错误资料继续编。

开发者：应该如何接入

  • LangChain：LCEL 链式编排，生态最全
  • LlamaIndex：以检索为中心的轻量框架
  • 向量数据库：Chroma / FAISS / pgvector
  1. 文档切块
  2. 块转 embedding 存向量库
  3. 用户问题转向量
  4. 检索最相关的几块
  5. 片段拼进 prompt
  6. 模型基于片段生成并引用
