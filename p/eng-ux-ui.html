UX 与 UI

好看是 UI，好用是 UX
👀 日常场景

有人说“这个 App 真好看”，有人说“这个 App 真好用”——前者在夸 UI，后者在夸 UX。招聘时“UI/UX 设计师”总被写在一起，很多人以为是一个东西。其实它们分工完全不同：一个管长相，一个管全程的感受。

原理：它是怎么运作的

💡 UI 是看得见的界面（颜色、排版、图标），UX 是用起来的全部感受（流程顺不顺、找不找得到）；UI 是 UX 的子集。

先看全过程

  1. 用户研究：搞清用户是谁
  2. 画线框图定信息结构
  3. 做可点击原型走流程
  4. 视觉设计定稿 UI
  5. 标注切图交付开发
  6. 可用性测试验证 UX

先分清楚：UX（用户体验）是“从产生需求到完成任务”的全程感受，UI（用户界面）只是其中“看得见摸得着”的一层——颜色、排版、图标、动效。UI 是 UX 的子集：一个按钮做得再好看（UI 满分），如果藏在三级菜单里找不到（UX 零分），用户照样骂。

为什么总被放在一起说？因为都向“用户体验”负责，而且工作流连贯：UX 定骨架（信息架构、任务流程），UI 填血肉（视觉风格）。招聘时写“UI/UX 设计师”，招的往往是一个人干两件事。

设计师的产出物沿着一条线流向开发：线框图（低保真，只定结构不谈美观）→ 高保真原型（可点击，走通流程）→ 视觉稿（定样式）→ 标注加切图加设计系统（Design System：组件库加使用规范，开发照着拼）。现代协作在 Figma 里一次完成：设计、标注、切图、评论都在同一份文件，开发不用再问“这个间距是多少”。

最后记住：UX 不止视觉。文案写得清不清楚、报错提示给不给退路、加载要等几秒、空状态放什么图——用户感知到的每一处，处处是 UX。

想深入了解怎么办

  • 《Don't Make Me Think》：UX 入门圣经，薄薄一本，核心就一句：别让用户思考。先读它，再谈别的。
  • NN/g 的免费文章：尼尔森诺曼集团的可用性研究报告，公认的 UX 方法论源头，官网有大量免费内容。
  • Figma 官方教程 + 社区：边学边练：从线框图到高保真原型，官方教程带你走完一遍真实工作流。
  1. 先分清边界：UX 是全程感受，UI 是看得见的界面——UI 只是 UX 的子集
  2. 学信息架构：用户要完成任务，信息该怎么组织、流程该有几步
  3. 练线框图和可点击原型：低保真先把流程走通，别一上来就调颜色
  4. 补视觉基础：排版、色彩、间距、对齐——UI 的“基本功四件套”
  5. 学做可用性测试：找 5 个真实用户，看他们在哪卡住（比看 10 本书管用）
  6. 研究优秀产品的设计系统：看它们如何把组件和规范沉淀成团队资产
