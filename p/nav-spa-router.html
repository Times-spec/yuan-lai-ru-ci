SPA 路由：不刷新页面的跳转

页面不刷新，地址栏却在变
👀 日常场景

刷着后台管理系统点左侧菜单，内容区瞬间切换，地址栏从 /users 变成了 /orders，但页面没有闪一下、没有重新加载。这就是单页应用的前端路由：地址变了，页面没重载。

原理：它是怎么运作的

💡 浏览器不向服务器发请求，靠 JS 监听地址变化（hash 或 history API），自己决定显示哪个页面组件。

先看全过程

  1. 用户点击站内链接
  2. JS 拦截默认跳转行为
  3. 用 history.pushState 改地址栏
  4. 按新路径渲染对应组件
  5. 浏览器前进后退照常工作

传统网站每换一个页面，浏览器都要重新请求、整页刷新；单页应用（SPA）只加载一次，之后页面切换全靠 JS 在本地完成，这就是前端路由。实现有两种：hash 模式用地址栏 # 后面的部分做路标，监听 hashchange 事件切换页面，# 后的内容不会发给服务器，所以纯静态托管也能跑，代价是网址里多个 # 不太好看；history 模式用 HTML5 的 pushState 直接改地址栏（/users → /orders），网址干净，但用户刷新或直接访问 /orders 时，服务器会真的去找这个路径——如果没做 fallback 配置就会 404，所以 history 模式要求服务端把所有未知路径都返回 index.html。前端路由让 Web 有了 App 般的流畅体验，代价是首屏只是一张空 HTML，搜索引擎基本看不懂，需要服务端渲染（SSR）或预渲染来补。

开发者：应该如何接入

  • Hash 模式：地址带 #，无需任何服务端配置
  • History 模式：地址干净，需服务端 fallback 配合
  • 框架路由库：Vue Router、React Router 开箱即用
  1. 选 hash 还是 history：静态托管选 hash，正式产品选 history
  2. 用框架路由库定义路径与组件的映射表
  3. history 模式要在 Nginx 或网关配 fallback：未知路径返回 index.html
  4. 加上路由守卫：未登录访问管理页先跳登录页
  5. 处理滚动位置、页面标题随路由更新
