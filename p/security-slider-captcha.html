滑块拼图验证

拖一下滑块，它看的其实是你的手
👀 日常场景

登录时页面弹出一个缺了一块的拼图，提示你“拖动滑块完成拼图”。你拖过去对准缺口，进度条一闪“验证通过”。你可能没意识到：拼得准不准只是顺带，它真正记录的是你拖动时手的轨迹。

原理：它是怎么运作的

💡 拼图只是幌子，真正的判决依据是拖动轨迹里的人类行为特征。

先看全过程

  1. 前端展示带缺口的拼图和滑块
  2. 记录拖动全过程：速度、加速度、停顿
  3. 采集设备环境：UA、分辨率、触屏参数
  4. 把轨迹特征发给风控服务打分
  5. 低风险直接通过，高风险加码挑战
  6. 服务端二次校验签名防伪造

滑块验证的高明之处在于“一石二鸟”：拼图缺口给用户一个明确的任务，而真正的验证发生在后台。真人拖动滑块时，手指或鼠标的运动天然带有随机性——起步有加速、接近缺口会减速微调、偶尔还会抖一下；机器脚本的轨迹则往往过于平滑均匀，或者是简单的直线+固定时长。风控服务会采集几十维特征：拖动速度曲线、加速度变化、停顿次数、抖动幅度，再加上设备指纹、IP 信誉、请求时序等，用机器学习模型打出风险分。拼得准只是必要条件，轨迹像人才是充分条件。所以你偶尔会遇到“明明拼对了却说验证失败”的情况——那不是拼图的问题，是你的操作行为（比如用脚本、网络环境异常）被判定为高风险。服务端最后还会校验前端传回数据的签名，防止有人直接伪造“验证通过”的结果发给后端。这也解释了为什么手机上滑块更好过：触屏的压力和接触面积变化是模拟器最难伪造的信号之一，真人的手指自带“生物随机性”。

网站该如何接入

  • 极验 GeeTest：国内行为验证的开创者，滑块/点选/无感全套方案。
  • 网易易盾：网易旗下的内容安全与验证码服务。
  • 阿里云验证码：阿里云官方验证码，含滑块和无感验证。
  • 顶象：主打设备指纹+行为验证的风控厂商。
  1. 在服务商后台创建验证应用，拿到 id 和 key（key 只放后端）。
  2. 前端引入服务商 JS SDK，在登录/注册按钮处初始化滑块组件。
  3. 用户完成拖动后，SDK 返回验证凭证（challenge/validate/secrete 等）。
  4. 前端把凭证连同业务表单一起提交到自己后端。
  5. 后端用 key 调用服务商二次验证接口，确认凭证真实有效。
  6. 二次验证通过后再执行业务逻辑（发短信、建账号等）。
