Elasticsearch 全文搜索

全文搜索，快得像查字典
👀 日常场景

在知识库里搜「报销流程」，0.1 秒就列出所有相关文档，还按相关度排好序。数据库的 LIKE '%报销%' 遇到几十万行就跪了——Elasticsearch 靠「倒排索引」这种数据结构，把搜索变成了查表，自然快如闪电。

原理：它是怎么运作的

💡 用倒排索引预先建好「词→文档」映射，全文搜索变成查表加排序。

先看全过程

  1. 文档写入 ES
  2. 分词器把文本切成词
  3. 建立倒排索引：词→文档列表
  4. 用户输入搜索词
  5. 查倒排表找到候选文档
  6. 按相关度打分排序返回

数据库是为「精确查」设计的，全文搜索是它的天敌：LIKE '%关键词%' 无法走索引，只能逐行扫描。倒排索引反其道而行：正排是「文档→含有哪些词」，倒排是「词→出现在哪些文档」。建索引时先把文本分词（中文分词比英文难，IK、jieba 都是干这个的），然后为每个词记录它出现过的文档 ID 和位置。搜索时直接查表，毫秒级返回。

排序靠相关度打分（BM25 算法）：词在文档里出现越频繁、越稀有（全网很少文档包含它），得分越高。ES 是分布式的：数据按分片（shard）散到多个节点，并行搜索再汇总，副本（replica）保证挂一台不丢数据。

但 ES 不是数据库：它是「近实时」的，写入后约 1 秒才可搜；也不适合做事务和关联查询。正确姿势是 MySQL 存原始数据，ES 只存需要搜索的字段，用 MQ 或 Canal 同步。

开发者：应该如何接入

  • Elasticsearch：功能最全，生态最大
  • Meilisearch / Typesense：轻量，开箱即用，中文友好
  • 数据库全文索引：MySQL/PostgreSQL 自带
  1. 确定要搜索的字段，只同步这些进 ES
  2. 选分词器：中文用 IK 或 jieba，建索引 mapping
  3. 用 Logstash/Canal 或 MQ 把 MySQL 数据同步过去
  4. 写查询 DSL：match 查询 + 高亮 + 分页
  5. 按业务调权重：标题匹配加分、时间衰减
  6. 监控分片状态，数据量涨了及时扩容

相关条目

  • MySQL 索引 没有它，百万行查询要 10 秒
  • 云服务器 ECS：租一台弹性电脑 随开随关、随时升降配的电脑
  • Fake-IP：Clash 的 DNS 骗术 先给浏览器一个假地址，稳住它
