Embedding：词语的语义坐标

语义第一次变得可计算
👀 日常场景

"向量数据库""以文搜文""语义搜索"——搜"好吃的川菜馆"能返回"正宗麻辣火锅"，靠的不是关键词匹配。背后是一套把"语义"变成"空间距离"的数学，叫 Embedding。

原理：它是怎么运作的

💡 把 token ID 变成稠密向量，语义相近的词在空间里距离近——语义第一次变得可计算。

先看全过程

  1. token ID 进 embedding 层查表
  2. 得到几百维的稠密向量
  3. 训练中向量被推拉调整
  4. 近义词在空间里聚拢
  5. 向量可做加减类比运算
  6. 存入向量库支持语义检索

Token 解决了"变数字"，但 ID 只是编号："猫"是 1234、"狗"是 5678，数字之间没有任何关系，模型看不出猫狗比猫车更像。Embedding 解决的就是"给数字注入语义"。

它背后的思想叫分布假说：上下文相似的词，语义就相似。"猫爱吃鱼""狗爱吃骨头"里，猫和狗出现在相似的上下文中，训练时它们的向量就被推到一起。几百轮之后，"国王-男人+女人≈女王"这种类比竟然在向量空间里成立——语义第一次变得可计算。

在逻辑链上，Embedding 是 Token 的下一站：Token 给出离散 ID，Embedding 给出连续语义。它的直接产物就是今天的"向量数据库"和语义搜索，也是后面 RAG（检索增强生成）的地基——RAG 本质上就是"把问题变成向量，去向量库里找最像的文档"。

开发者：应该如何接入

  • sentence-transformers：all-MiniLM-L6-v2 又小又好用的句向量模型
  • OpenAI Embeddings API：text-embedding 系列，按量计费
  • 向量数据库：FAISS / Chroma / pgvector
