链式代理：把代理串成糖葫芦

一跳不够，串三跳
👀 日常场景

你在 VPS 上跑爬虫，只配一个代理还是被目标网站认出来；朋友说“套两层试试”——可代理又不是糖葫芦，怎么“套”？链式代理就是把几跳代理像糖葫芦一样串起来，流量一站一站往前传，每一跳都只认识它的上一跳和下一跳。

原理：它是怎么运作的

💡 链的本质是每跳主动连下一跳：电脑连代理 1，让它去连代理 2，代理 2 再连目标。proxychains、SSH 跳板机、Tor 都是这种接力的不同实现。

先看全过程

  1. 链=多跳接力，每跳连下一跳
  2. 交接靠 CONNECT/SOCKS 握手
  3. proxychains：给任意程序套链
  4. 三种串法：严格/动态/随机
  5. SSH -J：跳板机串糖葫芦
  6. Tor：自动搭好的三跳链

链式代理的本质是“每跳主动连下一跳”。你的电脑连上代理 1，然后对它说“帮我连代理 2”（HTTP 代理用 CONNECT 方法，SOCKS 代理用握手协议）；代理 1 连上代理 2 后交棒，代理 2 再连目标。数据像坐接力车，一站站换车，每一站只认识它的前后两站。

Linux 下有个神器叫 proxychains：劫持程序的网络调用，让不支持代理的程序也走链。配置文件里列出代理，三种串法：strict_chain 按序全通、一挂全挂；dynamic_chain 跳过死节点；random_chain 随机抽几个。记得开 proxy_dns，不然 DNS 直连暴露行踪。

运维常用 SSH 跳板机：ssh -J 跳板机 目标机，一条命令穿两跳，还能在配置文件里固化。而 Tor 是最著名的链：固定三跳（入口→中继→出口），层层加密如洋葱，还会自动选路、定期换路。

代价也直白：延迟叠加，链越长越慢，3 跳是甜点；经手人越多风险点越多，出口走明文 http 照样被看光——HTTPS 是最后一道防线。

我该怎么搭一条链

  • proxychains（Linux）：劫持任意程序的网络调用，强行走链；配好列表，命令前加前缀即用
  • SSH 跳板机 -J：一条命令穿两跳，配置可固化；运维连内网的标配
  • Tor 浏览器：开箱即用的三跳洋葱链，自动选路换路
  1. 准备 2~3 个可用的代理，出口不同更好
  2. proxychains：编辑 /etc/proxychains.conf 列出它们
  3. 选模式：求稳用 strict，求活路用 dynamic
  4. 打开 proxy_dns，防止 DNS 泄露
  5. 命令前加 proxychains4 前缀，验证出口 IP 变了
  6. SSH 跳板：ssh -J 跳板机 目标机，一步到位
