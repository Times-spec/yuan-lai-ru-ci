Fake-IP：Clash 的 DNS 骗术

先给浏览器一个假地址，稳住它
👀 日常场景

配置文件的 dns 一节里，总有个 fake-ip 开关。给浏览器返回“假 IP”？这听起来像骗人——但恰恰是这个“骗术”，解决了 Clash 分流里最头疼的 DNS 难题。

原理：它是怎么运作的

💡 Clash 的 DNS 不做真实解析，直接返回假 IP 并记下映射；浏览器拿假 IP 来连接时，Clash 查表找回真实域名再匹配规则，真实解析交给远端节点。

先看全过程

  1. 浏览器查询域名的 IP
  2. Clash 的 DNS 模块拦截请求
  3. 返回假 IP（如 198.18.0.x）并记录映射
  4. 浏览器拿着假 IP 来建连
  5. Clash 查映射找回域名并按规则匹配
  6. 走代理的由远端节点做真实解析

为什么需要这个“骗术”？因为 Clash 的规则大多是按域名写的（DOMAIN-SUFFIX），但浏览器发起连接前要先有 IP。传统做法是：Clash 自己先做一次真实 DNS 解析，拿到真 IP 再走规则。可这就撞上了两堵墙：一是 DNS 污染——解析结果可能是假的，拿着被污染的 IP 去连，注定失败；二是 DNS 泄露——本地解析请求本身就暴露了你在访问什么。

Fake-IP 的思路是釜底抽薪：本地根本不做真实解析。浏览器问“google.com 的 IP 是多少”，Clash 从保留段（198.18.0.0/16）里随手给一个假 IP，同时在内存记下“这个假 IP = google.com”。浏览器拿着假 IP 来建连，Clash 查表找回域名，按域名走规则；命中代理的，把域名原样交给远端节点，由节点在干净的网络环境里做真实解析。

还有个配套概念 fake-ip-filter：有些域名不能拿假 IP，比如内网服务、网银——它们要直连，必须给真 IP，所以要列入白名单。

它的前任叫 redir-host（直接返回真实 IP），污染和泄露问题太多，已被取代。Fake-IP 也不是完美的：如果 Clash 异常退出，浏览器还缓存着假 IP，会短暂打不开网站——不过 DNS 响应的 TTL 被设得很短（1 秒），等缓存过期就好。

🌀 如果没有它会怎样

没有 Fake-IP，Clash 就得先在本地做真实解析：解析结果可能被污染，解析请求本身还会暴露你在访问什么——规则按域名写得再准，也没有干净的域名可用。

🚫 常见误解

解析到 198.18.x.x 就是中了毒或配错了。其实那是 Clash 故意发的假 IP：198.18.0.0/16 是保留段，专门用来占位，等连接发起时再回查真实域名。

要不要打开 Fake-IP

  • 打开（默认推荐）：本地不做真实解析，防 DNS 污染、防泄露，延迟还低
  • 关掉用真实解析：每个域名都做真实 DNS 查询，行为最“老实”
  • 开了 + 配白名单：内网域名、网银等走真实解析，其他走假 IP
  1. 默认建议：打开（dns 一节 enhanced-mode: fake-ip）
  2. 把内网域名（*.lan、*.local、公司域名）加进 fake-ip-filter 白名单
  3. 网银、政务网站如果异常：先加白名单，再试
  4. 出问题时关掉对比一下：好了就是假 IP 的锅
  5. 异常退出后打不开网站：清一下 DNS 缓存，或等几秒（TTL 只有 1 秒）
