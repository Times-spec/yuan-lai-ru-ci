表单草稿自动保存

写到一半关掉，回来还在
👀 日常场景

写长评论、发帖子写到一半，不小心关了页面或浏览器崩了，心里一凉。重新打开，发现刚才写的内容居然还在，还贴心地提示“已为你恢复草稿”——那一刻你只想给产品经理加鸡腿。

原理：它是怎么运作的

💡 监听输入事件做防抖，把表单内容序列化存入 localStorage，下次打开页面时读出来回填。

先看全过程

  1. 监听表单输入事件
  2. 防抖后序列化表单数据
  3. 写入 localStorage 草稿
  4. 页面加载时检查草稿
  5. 有草稿则回填并提示
  6. 提交成功后清除草稿

原理很朴素：监听输入，存起来，下次回填。表单的每个 input 事件触发时（做防抖，比如停 500ms 再存，别每敲一个字写一次），把表单数据序列化成 JSON，按“用户+表单”拼个唯一的 key 存进 localStorage；下次打开页面，先查有没有这个 key，有就回填并提示“已为你恢复草稿”。localStorage 是浏览器的同源小仓库（约 5MB），存取都是同步的，够放文字草稿。为什么不用 cookie？cookie 每次请求都会带上服务器，存草稿纯属浪费带宽。几个必须注意的点：一是隐私：密码、身份证号、银行卡这类敏感字段千万别进 localStorage，它没有任何加密，XSS 攻击能直接读走；二是 key 要隔离：多用户共用一台电脑、同一页面多个表单，key 得带上用户 id 和表单 id，不然会串；三是配额：localStorage 写满会抛异常，try/catch 包住；四是“清草稿”时机：提交成功一定要删，否则下次打开又冒出已发布的内容。登录用户的跨设备草稿则是另一条路：存服务端接口，换设备也能续写。

我的草稿存在哪

  • 存在这台设备的浏览器里：草稿存在 localStorage——浏览器自带的小仓库，约 5MB，专门放这种“本机小数据”。
  • 只在这台设备、这个浏览器有效：换台手机、换个浏览器，草稿都跟不过去。它不是存在网站的服务器上的。
  • 提交成功就自动清除：内容一旦成功发出，草稿就被删掉。下次打开是干干净净的新表单。
  1. 你写着写着，页面每隔一会儿自动把内容存进浏览器
  2. 不小心关了页面、浏览器崩了，都不慌
  3. 重新打开，页面提示“已为你恢复草稿”
  4. 点恢复，接着写；写完提交，草稿自动清除
