CDN 内容分发网络

让你访问的总是隔壁的服务器
👀 日常场景

你在北京刷 B 站，视频却秒开——视频文件根本不在 B 站的中央机房，而是提前复制到了离你最近的 CDN 节点上。CDN 就是遍布全国的「前置仓」：热门内容提前铺货，用户就近取货，源站压力骤减。

原理：它是怎么运作的

💡 把静态资源复制到离用户最近的边缘节点，就近返回，源站只做回源兜底。

先看全过程

  1. 用户请求图片/视频资源
  2. DNS 把用户导向最近节点
  3. 节点有缓存：直接返回
  4. 节点无缓存：回源站取
  5. 源站返回并写入节点缓存
  6. 后续同地区用户直接命中

CDN 的本质是「空间换时间 + 就近服务」。互联网的主干延迟摆在那：北京用户访问广州机房，光是物理距离就要几十毫秒；CDN 在全国铺了成千上万个边缘节点，通过 DNS 调度把用户引到最近的节点，静态资源（图片、视频、JS、CSS）直接从节点内存/SSD 返回，延迟能压到几毫秒。

关键指标是缓存命中率：命中越高，源站越轻松。靠 Cache-Control 头控制缓存时间；文件更新用「换文件名」而非「清缓存」（webpack 的 hash 命名就是为这个）。回源是兜底：节点没缓存才去源站取一次，然后大家共享。

动态内容也能加速：TCP 优化、链路复用、边缘计算让动态请求走更优路径。但 CDN 不适合强一致场景——刚上传的头像，异地用户可能要等缓存过期才看得到。调试缓存有个小技巧：看响应头里的 X-Cache 或 Age 字段，HIT 表示命中节点缓存，MISS 表示回源了——排查「为什么还是旧内容」先看它。

开发者：应该如何接入

  • 阿里云/腾讯云 CDN：国内节点最多，备案域名即开即用
  • Cloudflare：免费套餐慷慨，自带防护
  • AWS CloudFront：和 S3 深度集成
  1. 把静态资源域名（如 cdn.example.com）接入 CDN
  2. 配置源站地址，CDN 回源去这里取文件
  3. 设置缓存规则：图片视频缓存久，HTML 不缓存
  4. 发布新版本时用文件名 hash，避免缓存未更新
  5. 观察命中率，低于 90% 就要排查规则
  6. 开启 HTTPS 和防盗链，保护源站不被刷
