Benchmark：给大模型的标准化考试

大模型的高考，分数也会通胀
👀 日常场景

新闻"某模型在 MMLU 上得分第一，超越 GPT"——这考试到底考什么？为什么有的榜单大家分数都挤在 90% 上动不了，而有的榜单还能拉开几十分的差距？这套考试系统就是 Benchmark。

原理：它是怎么运作的

💡 标准化考试=数据集+指标+流程；MMLU 考广度、HumanEval 考代码、GPQA 考推理，考题会"饱和"倒逼更难的卷子。

先看全过程

  1. 定考题：准备数据集
  2. 定评分规则：指标
  3. 统一条件下让模型作答
  4. 打分、排名、公布
  5. 旧卷子被刷到饱和
  6. 出更难的新卷子，循环

没有统一考试，各家发布会都可以自称第一。Benchmark 就是大模型的"高考"：标准化考卷=数据集+指标+流程，让不同模型可比较、可复现。四个最出名的各测一面：MMLU 是 57 学科 1.57 万道选择题，测知识广度；HumanEval 是 164 道 Python 函数题，跑过单元测试才算对；GPQA 是理科研究生级难题，专家开卷也只有约 65%；SWE-bench 直接给真实 GitHub issue 和代码库，模型要读 issue、写 patch、跑测试。

关键概念是"饱和度"：MMLU 前沿模型已超 92%，标签错误把上限卡在约 95%——卷子刷完，分数涨不动了；HumanEval 同理。而 GPQA Diamond 和 SWE-bench Verified 还能拉开差距，于是形成军备竞赛：旧卷饱和→出更难的新卷（MMLU-Pro、Humanity's Last Exam）。在逻辑链上，评测是整条链的质检员，也是下一环 Harness 存在的原因——没有统一执考，考卷再好也白搭。

选模型时怎么看榜单

  • 综合大榜：Open LLM Leaderboard 这类：多个任务平均分，看个大概座次
  • 按场景看专项：写代码看 HumanEval/SWE-bench，数学看 MATH，知识看 GPQA
  • 价格性能榜：Artificial Analysis 这类：把分数和 API 价格放一起看
  1. 先定你的场景：聊天、写代码、还是知识问答——榜单要对口
  2. 去综合榜看个大概，圈出 3～5 个候选
  3. 去专项榜验证：只看和你场景相关的那 1～2 个分数
  4. 看饱和度：MMLU 这种大家挤在 90%+ 的榜，1～2 分差距基本是噪声
  5. 拿你自己的真实任务实测一轮：榜单≠你的业务效果
  6. 最后看价格：便宜 10 倍、分数差 2 分，多数场景选便宜的
