页面自动跳转：meta 与 JS

服务器不说话，浏览器自己数完秒就走
👀 日常场景

注册成功后看到“5 秒后自动跳转到首页”的倒计时；老网站里“如果没有自动跳转请点击这里”的提示页。这些跳转不是服务器发的指令，而是网页自己用代码实现的。服务器只给了页面，跳转的活儿全由浏览器自己干。

原理：它是怎么运作的

💡 不走 HTTP 状态码，靠 HTML 的 meta refresh 标签或 JS 的 location 跳转在浏览器端触发页面切换。

先看全过程

  1. 浏览器先完整加载当前页面
  2. meta 标签或 JS 定时器启动
  3. 倒计时结束触发跳转
  4. 浏览器请求新地址
  5. 地址栏更新但无状态码语义

服务端跳转是服务器在 HTTP 层面直接发号施令，而客户端跳转是“页面自己动”。meta refresh 是写在 HTML 头里的一条指令，告诉浏览器“几秒后去这个地址”；JS 跳转则是代码里调用 location.href（普通跳转，会留下历史记录）或 location.replace（替换当前记录，点回退回不去）。它们的共同点是：浏览器先完整加载了当前页面，才执行跳转，所以你会看到“5 秒后自动跳转”的倒计时页。这种方式有两个硬伤：一是对搜索引擎不友好，权重传递几乎为零，还可能被判定为作弊；二是容易被钓鱼网站利用——先给你看正常内容，几秒后悄悄跳到假冒页面。也正因如此，现代开发都优先用服务端 301/302。客户端跳转只建议用在两种地方：纯静态托管改不了服务端配置时，以及登录态失效这类需要前端先判断、再用 replace 跳转不留痕的场景。

开发者：应该如何接入

  • meta refresh 标签：纯 HTML 实现，零 JS，支持倒计时
  • location.href：条件满足后 JS 跳转，可带业务逻辑判断
  • location.replace()：替换当前历史记录，用户点回退不会回到跳转页
  1. 优先评估能否用服务端 301/302 替代
  2. 倒计时页用 meta refresh，秒数不宜超过 5 秒
  3. 同时放一个可点击链接，兜底自动跳转失败
  4. 登录态校验失败等安全跳转，用 replace 避免回退
