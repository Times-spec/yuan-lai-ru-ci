npm / Node.js

让 JS 走出浏览器的两个人
👀 日常场景

你想写个小工具批量改文件名，敲下 npm install，几秒钟后依赖装好，工具跑起来了。十几年前不可想象：JS 只能活在浏览器，想复用代码只能复制粘贴。Node.js 和 npm 联手终结了那个时代。

原理：它是怎么运作的

💡 Node.js 把 V8 引擎搬出浏览器，让 JS 能读写文件、开服务；npm 是它的应用商店，一行命令装走全世界开源代码。

先看全过程

  1. 2009 年：Node.js 发布
  2. V8 引擎 + 事件循环 + 系统 API
  3. JS 第一次能读写文件、监听端口
  4. 开源包爆发式增长，复用成刚需
  5. npm 诞生：统一的包仓库 + 安装命令
  6. package.json 成为项目的身份证

Node.js 的本质是“换了宿主的 JS”：浏览器里的 JS 能操作 DOM 但碰不到文件系统；Node.js 把 Chrome 的 V8 引擎抽出来，配上事件循环（event loop，一种“单线程处理高并发”的模型）和文件、网络等系统 API，JS 从此能写服务端、写脚本、写工具。

但语言能跑只是第一步。很快大家发现：每个项目都要处理日期、发 HTTP 请求、解析 Excel，重复造轮子太蠢。npm（Node Package Manager）就是答案：一个中央仓库 + 一条安装命令，`npm install dayjs`，全世界的开源代码任你取用。今天 npm 上有数百万个包，前端工程化的地基。

package.json 是每个 Node 项目的“身份证”：name/version 标识身份，scripts 把常用命令起别名（`npm run dev`），dependencies/devDependencies 记录依赖及版本。配合 lock 文件（package-lock.json），保证“你装的和我装的是同一套版本”——终结了“在我电脑上是好的”这句经典甩锅。

开发者：应该如何接入

  • npm：Node 官方自带，最通用
  • pnpm：硬链接共享依赖，又快又省磁盘
  • yarn：老牌替代品，berry 版特性激进
  1. 官网装 LTS 版 Node.js，自带 npm
  2. 项目根目录 npm init，一路回车生成 package.json
  3. npm install <包名> 装依赖，--save-dev 装开发依赖
  4. 把常用命令写进 scripts，一句 npm run 启动
  5. 提交代码时带上 lock 文件，不提交 node_modules
