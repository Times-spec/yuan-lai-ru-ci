支付成功回跳：回到商户页面

付完钱，先给你看个“支付成功”页面
👀 日常场景

在淘宝买东西点“去支付”，跳到支付宝付完款，页面又跳回淘宝显示“支付成功”。这个跳回来的页面就是同步回跳，但它只负责展示，不能当作“真的收到了钱”的证据。把它当成迎宾员就好，真正的账本另有其人。

原理：它是怎么运作的

💡 用户在支付平台付完款，支付平台用浏览器 302 把用户带回商户预设的 return_url 页面；它只负责展示，支付结果不可信，一切以异步通知为准。

先看全过程

  1. 用户在商户站点击去支付
  2. 跳到支付平台完成付款
  3. 支付平台 302 带回商户页面
  4. 商户展示成功或处理中页面
  5. 真实结果等异步通知确认

同步回跳是支付流程的“迎宾页”：你在支付宝付完款，支付宝用浏览器把你 302 带回商户预设的 return_url，商户展示“支付成功”或“处理中”。但它有三个不可靠：用户付完款可能直接关页面，回跳根本不会发生；回跳走的是用户浏览器，参数可能被篡改；网络抖动也可能让回跳丢失。所以铁律是：return_url 只做展示，绝不依据它的参数修改订单状态。正确姿势是回跳页收到请求后，主动调支付平台的查单接口核实，确认成功再展示“支付成功”，没确认就展示“处理中”，并引导用户稍后在订单页查看。真正的订单状态变更，要等异步通知（notify_url）来了再做。开发时还有个细节：return_url 必须是公网可访问的地址，支付平台是在用户浏览器里做 302，内网地址用户根本打不开。回跳页建议做成“查询中”的过渡态：先展示加载态，后台调查单接口，有了结果再渲染成功或失败，避免页面长时间白屏。

开发者：应该如何接入

  • 支付宝 return_url：签约时配置页面跳转同步通知地址
  • 微信支付前端回跳：JSAPI 支付完成后前端按业务跳回
  • 通用做法：return 页只做查询展示，不做状态变更
  1. 在支付平台商户后台配置 return_url（公网可访问）
  2. 下单时把订单号等业务参数带上
  3. return 页面收到回跳后，调支付平台查单接口核实
  4. 页面展示“支付成功”或“处理中”，不直接改订单状态
  5. 真正的订单状态变更只在异步通知里做
