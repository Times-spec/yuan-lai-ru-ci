Docker 容器

终结「在我电脑上明明是好的」
👀 日常场景

程序在开发电脑上跑得好好的，一上服务器就报错：缺库、版本不对、路径不同。Docker 把应用连同操作系统依赖打包成镜像，哪里运行都是一模一样的环境——开发、测试、生产终于不再「各说各话」。

原理：它是怎么运作的

💡 把应用和依赖打成镜像，容器是镜像的运行实例，一次构建、处处运行。

先看全过程

  1. 编写 Dockerfile 描述构建步骤
  2. docker build 生成镜像
  3. 镜像分层存储，可复用共享
  4. docker run 启动容器实例
  5. 容器间相互隔离、资源受限
  6. 删容器不影响镜像，随时重建

Docker 解决的是「环境不一致」这个千古难题。传统部署靠文档和运维手工装环境，差一个库版本就可能崩；Docker 把应用代码、运行时、系统库、配置文件全部打进镜像（image），镜像是只读模板，容器（container）是它的运行实例——就像类和对象的关系。

技术上靠 Linux 的两大机制：Namespace 做隔离（每个容器有独立的进程、网络、文件系统视角），Cgroups 做资源限制（这个容器最多用 2 核 4G）。和虚拟机相比，容器没有 Guest OS，启动是毫秒级，一台机器能跑几十上百个。

镜像采用分层存储：每一行 Dockerfile 指令产生一层，相同的基层（如 Python 3.12）在多个镜像间共享，既省磁盘又加快拉取。多阶段构建（multi-stage build）是常用优化：编译阶段用大镜像，运行阶段只拷二进制文件，镜像体积能从 1GB 压到几十 MB。

开发者：应该如何接入

  • Docker Engine：官方容器运行时，事实标准
  • Docker Desktop：带图形界面的桌面版
  • Podman：红帽主推的无守护进程替代品
  1. 安装 Docker，跑通 docker run hello-world
  2. 为项目写 Dockerfile：选基础镜像、拷代码、装依赖
  3. 用 .dockerignore 排除 node_modules、.git 等无用文件
  4. docker build -t myapp:1.0 . 构建镜像
  5. docker run -d -p 8080:8080 myapp:1.0 启动验证
  6. 推送到镜像仓库，服务器上拉取运行
