本机号码一键登录

点一下就登录，连短信都不用等
👀 日常场景

打开某个 App，登录页一个大按钮“本机号码一键登录”，下面已经自动填好了你的手机号（138****8888），点一下直接进去了。你没收短信、没输密码——它怎么知道这个号码是你的？

原理：它是怎么运作的

💡 走数据网络经运营商网关“取号”：运营商认 SIM 卡，把加密后的号码回传给 App。

先看全过程

  1. App 初始化时向取号 SDK 注册
  2. 用户点一键登录（需关闭 Wi-Fi 走蜂窝数据）
  3. SDK 经运营商网关发起取号请求
  4. 运营商识别 SIM 卡对应的手机号
  5. 返回加密的号码凭证 token
  6. App 后端用 token 换取真实号码完成登录

一键登录的魔法来自运营商的一个特权：当手机走蜂窝数据（关闭 Wi-Fi）访问运营商网关时，运营商能直接识别出这张 SIM 卡对应的手机号——这是网络层的能力，不需要 App 做任何事。流程是：App 集成取号 SDK，用户点击一键登录后，SDK 通过数据网络向运营商网关发起取号请求，运营商确认 SIM 卡身份后，返回一个加密的 token（注意：明文号码不会经过 App 前端）；App 把 token 发给自己的后端，后端再调用运营商/服务商的接口，用 token 换取真实手机号，然后完成登录或注册。为什么必须关 Wi-Fi？因为取号依赖的是运营商数据通道的身份识别，走 Wi-Fi 时运营商看不到你的 SIM 卡。这项能力的本质是“运营商为你的手机号背书”，安全性和短信验证码相当，但体验是秒级的，还省了短信费用。缺点是只认“本机+数据网络”：双卡手机、平板、Wi-Fi 环境都会降级回短信验证。

网站该如何实现

  • 阿里云号码认证 PNVS：阿里云官方一键登录/号码认证产品。
  • 极光认证：极光的一键登录方案，覆盖三网。
  • 个推 / 友盟一键登录：推送厂商附带的一键登录能力。
  • 运营商能力开放平台：移动/联通/电信各自的直连接口。
  1. 在服务商后台开通一键登录，配置 App 包名、签名和应用信息。
  2. App 集成 SDK，启动时做预取号（预先向网关拿 token，缩短点击后等待）。
  3. 登录页展示“一键登录”按钮，调用 SDK 拉起运营商授权页（含号码明示）。
  4. 用户点同意后，SDK 返回 token，App 把 token 发给自己后端。
  5. 后端调用服务商“token 换手机号”接口，拿到明文号码。
  6. 按号码查找/创建账号并建立登录态；取号失败时降级为短信验证码。
