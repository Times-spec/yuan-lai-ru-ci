WebRTC 泄露：代理开着，真 IP 却在裸奔

代理管得住网页，管不住浏览器的“悄悄话”
👀 日常场景

你人在雅安，连着美国住宅 IP 节点，打开检测网站：IP 一栏明明白白写着美国，可往下一滑，“泄露检测”后面赫然躺着 116.169.10.33——你的真实 IP。代理明明开着，它是怎么“告密”的？

原理：它是怎么运作的

💡 WebRTC 为打视频电话要直连对方，会绕过代理用 UDP 直接问 STUN 服务器“我是谁”，真实 IP 就这样被送了出去。

先看全过程

  1. WebRTC=浏览器里的视频通话
  2. 要直连，先问 STUN“我是谁”
  3. STUN 走 UDP，不走代理隧道
  4. 网站拿到你的真实公网 IP
  5. 192.168.x.x 不算泄露，别慌

WebRTC 是浏览器原生的实时音视频技术，网页版视频会议都靠它。为了建立最低延迟的直连，它用 ICE 协议“四处探路”，其中一步是向 STUN 服务器（多由 Google、Mozilla 运营）查询自己的公网 IP。

关键就在这里：这一步走 UDP 直连，不经过代理的隧道——代理只接管了 TCP 网页流量。于是检测网站从 STUN 那里拿到了你的真实 IP。截图就是案发现场：代理 IP 是美国 AT&T，真 IP 却是雅安的 116.169.10.33。

两个冷知识：一、看到 192.168.x.x 别慌，那是内网地址，只有公网 IP 暴露才算泄露；二、简单粗暴禁用 WebRTC 本身会变成显眼的浏览器指纹，在成熟风控眼里“正常用户很少关这个”，反而更可疑。所以正确姿势不是一关了之，而是让 WebRTC 走代理、或只在需要时开启。

怎么堵住这个泄露

  • Firefox：about:config：搜 media.peerconnection.enabled，设为 false，彻底关闭
  • Chrome/Edge：uBlock Origin：设置里勾选“防止 WebRTC 泄露本地 IP 地址”
  • Brave：原生设置：盾牌设置里把 WebRTC IP 政策改为“停用非代理 UDP”
  1. 先检测：打开检测站，看“泄露检测”一栏
  2. 真实公网 IP 出现=在泄露
  3. 按浏览器选上面的方法堵住
  4. 堵完复测一次，确认干净
  5. 定期复测：浏览器升级可能重置设置
