吸顶导航

往下滚，导航栏“粘”在顶部
👀 日常场景

刷一篇长文章或商品列表，往下滚时顶部的导航栏、搜索框像被胶水粘住一样停在屏幕上方，分类、搜索随时能点，不用费劲滚回顶部。电商的筛选栏、文档站的目录，经常这样“吸”着你。

原理：它是怎么运作的

💡 用 CSS position: sticky 让导航在滚动到顶部时“粘住”，或监听滚动动态切换 fixed 定位实现。

先看全过程

  1. 导航栏正常参与排版
  2. 滚动接近顶部阈值
  3. 切换为粘性固定定位
  4. 导航始终可见可点击
  5. 滚回顶部恢复原位
  6. 占位防止布局跳动

吸顶分两种实现，现代浏览器首选 CSS：给导航加 position: sticky; top: 0，滚动到它“顶到”视口顶部时，它就“粘”住了，滚回去又恢复原位——全程 GPU 友好，不用 JS。但 sticky 有个著名天坑：它只在父容器里有效，如果某个祖先元素设了 overflow: hidden（很多弹窗、轮播组件会设），sticky 直接失效，这是排查时的第一怀疑对象。老浏览器或复杂场景（比如滚动时导航栏收缩变矮、根据滚动方向隐藏/显示）就用 JS 方案：监听 scroll，超过阈值给导航加 fixed 定位，同时注意 fixed 会脱离文档流，下面的内容会“跳”上来，得在原位置留一个等高的占位 div。多个吸顶元素（比如导航加筛选栏）要排好 z-index 和 top 偏移，不然叠在一起打架。移动端还有个小技巧：iOS 的橡皮筋回弹滚动下，sticky 表现比 JS 方案稳得多。

网站是怎么做到的

  • CSS sticky：首选方案：给导航加 position:sticky;top:0，滚动到顶就“粘”住，滚回去恢复原位。全程 GPU 友好，不用一行 JS。
  • 祖先 overflow:hidden：头号天坑：sticky 只在父容器里有效。如果某个祖先元素设了 overflow:hidden（弹窗、轮播很爱设），sticky 直接失效。
  • JS fixed 兜底：老浏览器的备胎：监听 scroll，超阈值就切 fixed 定位。但 fixed 会脱离文档流，得在原位置留等高占位，不然内容“跳”上来。
  • iOS 橡皮筋：sticky 更稳：iOS 的回弹滚动下，sticky 表现比 JS 方案稳得多，JS 方案容易抖动。
  1. 导航栏正常参与页面排版，跟着内容一起滚
  2. 滚动到它“顶”到视口顶部的位置
  3. sticky 生效：导航“粘”在屏幕上方，不再往上走
  4. 分类、搜索随时可点，不用滚回顶部
  5. 往回滚：导航回到原位，一切如初
