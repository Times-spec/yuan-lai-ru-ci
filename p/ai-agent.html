AI 与大模型

智能体 Agent

从只会说，到会动手做事
👀 日常场景

Cursor 自动写代码改 bug、"AI 员工"自己操作软件——模型什么时候学会"动手"的？答案是：它其实没动手，它只是学会了指挥你的代码动手。这套"脑+手+心跳"的系统，就叫智能体 Agent。

原理：它是怎么运作的

💡 LLM（脑）+工具（手）+循环（心跳）：ReAct 循环里模型自己决定下一步调什么工具，从"说"到"做"。

先看全过程

  1. 用户给定目标
  2. 模型规划并拆解
  3. 选中工具，发出调用请求
  4. 外部执行，结果返回
  5. 模型观察再决策
  6. 循环直到目标完成

大语言模型有个根本局限：它只能"说"，不能"做"。它不知道今天天气，不知道你的数据库里有什么。Agent 的思路是：给模型配"手"（工具）和"心跳"（循环）。经典模式叫 ReAct：模型先思考（Thought）"我需要查天气"，再行动（Action）发出结构化的工具调用请求，外部编排器真正执行查询，把结果（Observation）喂回去，模型再决定下一步。

关键细节：模型从不真正执行工具——它只输出一段 JSON 说"请调用 get_weather，参数是上海"，执行的是你的代码。这意味着工具的权限边界完全由你控制，也意味着 Agent 的能力上限取决于你给了它什么工具。Cursor、Claude Code 这类 AI 编程工具，本质就是"代码版 Agent"：模型规划、调终端、读文件、跑测试，循环到 bug 修好。

在逻辑链上，Agent 承接"LLM 只能说"：RAG 给了它知识，Agent 给了它行动力。它是整条链从"智能"走向"生产力"的一跃——也是风险开始的地方：会行动的模型，才需要护栏。

我该怎么用它

  • AI 编程工具：Cursor、Claude Code 这类：给目标，它自己读文件、改代码、跑测试
  • 桌面/浏览器 Agent：能操作软件、填表格、逛网页的 Agent
  • 工作流 Agent：把"查资料→整理→发日报"这类固定流程交给它定时跑
  1. 从一件具体的小事开始：比如"把这个文件夹的截图按日期重命名"
  2. 目标一次只给一个，边界讲清：能碰哪些文件、不能碰哪些
  3. 让它先说计划再动手，计划不对直接叫停改计划
  4. 每一步的结果都看一眼，别当甩手掌柜
  5. 删文件、花钱、发消息这类敏感操作，设成必须人工确认
  6. 复盘：哪次它理解偏了，就把那条要求写进以后的指令里
