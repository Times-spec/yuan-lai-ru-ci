复制链接

点一下，链接就进了剪贴板
👀 日常场景

点“复制链接”按钮，页面弹出“已复制”，切到微信里粘贴，链接就发出去了——全程不用手动选中网址、不用按 Ctrl+C。优惠券口令、邀请链接、收货地址，处处都是这个小按钮。

原理：它是怎么运作的

💡 调用 Clipboard API 的 writeText 把文本写入系统剪贴板，需 HTTPS 且由用户点击触发，老浏览器用 execCommand 降级。

先看全过程

  1. 用户点击复制按钮
  2. 调用 Clipboard API 写文本
  3. 浏览器校验安全上下文
  4. 文本进入系统剪贴板
  5. 页面 toast 提示复制成功
  6. 失败时降级为手动复制

复制功能的核心是 Clipboard API：navigator.clipboard.writeText('文本')，一行代码把字符串写进系统剪贴板。但浏览器对此管得很严：必须是 HTTPS（或 localhost），且必须在用户手势（点击）中调用——这是为了防止恶意网站在你没察觉时偷偷改剪贴板（比如把你复制的收款地址换掉，这种攻击真实存在）。老浏览器的降级方案很“土”但有效：创建一个看不见的 textarea，把文本塞进去，全选，再调 document.execCommand('copy')，靠“模拟用户复制选中内容”蒙混过关。还有个细节：writeText 是异步的，返回 Promise，成功就弹个 toast“已复制”，失败（比如权限被拒）就降级或提示用户手动复制。移动端要注意，iOS 的 Safari 对 execCommand 支持一向挑剔，尽量走 Clipboard API。为什么有些网站点复制没反应？八成是页面不是 HTTPS，导致 navigator.clipboard 是 undefined，代码又没写降级。

网站是怎么做到的

  • Clipboard API：一行代码写剪贴板：navigator.clipboard.writeText('文本')，就这么一行，字符串就进了系统剪贴板。
  • 双重门禁：HTTPS + 用户手势：必须是 HTTPS 页面，且必须在“点击”这个动作里调用。防止恶意网站在你没察觉时偷换剪贴板（比如把你复制的收款地址掉包）。
  • 土法降级：看不见的 textarea：老浏览器没有 Clipboard API，就建一个看不见的文本框，把文字塞进去全选，再调 execCommand('copy')模拟“用户复制”。
  • 异步 + toast：成功才报喜：writeText 返回 Promise，成功了弹“已复制”，失败了降级或提示手动复制。
  1. 你点击“复制链接”按钮——注意，必须是你亲手点的
  2. 页面调用 clipboard.writeText，把链接字符串交给浏览器
  3. 浏览器检查：是 HTTPS 吗？是用户手势触发的吗？都通过才放行
  4. 文本写入系统剪贴板
  5. 页面弹出“已复制”toast
  6. 你切到微信粘贴，链接发出去了；如果失败，页面会降级提示你手动复制
