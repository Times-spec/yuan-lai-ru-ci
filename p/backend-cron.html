定时任务 Cron

每天凌晨三点，准时干活
👀 日常场景

每天凌晨，系统自动备份数据库、生成昨日报表；每月 1 号，账单准时推送到你邮箱。这些没人值守却从不迟到的活，都是定时任务干的——它就像一个不知疲倦的闹钟，到点就执行，风雨无阻，全年无休。

原理：它是怎么运作的

💡 按时间表达式周期性触发任务，备份、报表、对账这些脏活累活都靠它。

先看全过程

  1. 写好要执行的脚本或接口
  2. 用 cron 表达式定执行时间
  3. 注册到调度器
  4. 到点调度器触发执行
  5. 记录日志与执行结果
  6. 失败告警，人工介入

Cron 来自 Unix，表达式「分 时 日 月 周」五个字段描述周期，比如 0 3 * * * 就是每天凌晨 3 点。操作系统级的 crond 常驻后台，到点 fork 进程执行；应用层的调度器（Spring Scheduler、APScheduler、云函数触发器）原理相同，只是更贴近业务代码。

单机时代很简单，分布式时代就麻烦了：三台机器同时跑「每天清理过期订单」，就会清理三遍。解法有三种：只让一台机器跑（单点，有挂的风险）、抢分布式锁（谁抢到谁跑）、用分布式调度器（XXL-Job、ElasticJob，任务分片到多台）。

定时任务最怕「静默失败」：脚本挂了没人知道，三个月后才发现报表停更。所以每条定时任务都要有执行日志、成功率监控和失败告警。幂等也很重要——凌晨的任务如果因超时被重跑一次，不能重复发账单。

开发者：应该如何接入

  • Linux crontab：系统自带，零依赖
  • XXL-Job / ElasticJob：分布式调度，管理界面可查日志
  • 云函数触发器：按调用次数计费，免运维
  1. 把任务写成独立脚本，保证可重复执行（幂等）
  2. 用 cron 表达式确定执行周期，避开业务高峰
  3. 单机用 crontab -e 注册，集群用分布式调度器
  4. 输出日志到文件，关键步骤打点记录
  5. 配置失败告警：短信/邮件/群机器人
  6. 定期检查任务存活，别让它悄悄停了三个月
