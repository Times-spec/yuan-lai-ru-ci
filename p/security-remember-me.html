「记住我」持久登录

勾一下，下次打开直接是登录态
👀 日常场景

登录时勾选“记住我”或“两周内自动登录”，之后每次打开网站都是登录好的，连密码都不用输。你换过浏览器却发现要重新登录——这个“记住”到底记在了哪里？答案是：记在浏览器里的一块“免死金牌”Cookie 上。

原理：它是怎么运作的

💡 服务端签发长期有效的 HttpOnly Cookie；靠“刷新令牌轮换”机制，被盗能止损。

先看全过程

  1. 用户勾选记住我并登录成功
  2. 服务端签发长期凭证（数天~数月）
  3. 长期凭证存于 HttpOnly Cookie
  4. 每次访问后端校验凭证有效性
  5. 刷新令牌轮换：旧 token 用一次即废
  6. 发现 token 被盗用时吊销整条链

“记住我”的本质是把“登录”这件事的有效期拉长。普通会话 Cookie 关闭浏览器就失效，而勾选记住我后，服务端会签发一张长期凭证（有效期几天到几个月），存在 HttpOnly（JS 读不到，防 XSS 偷）+ Secure（只走 HTTPS）+ SameSite 的 Cookie 里。下次你打开网站，后端校验这张凭证有效，就直接恢复登录态——“记住”记的是服务端发的凭证，不是你的密码。安全设计的核心是“刷新令牌轮换”（refresh token rotation）：长期凭证设计成“用一次就换新的”，每次用旧 token 换新 token，旧的立即作废。这样即使 token 被偷走，攻击者和你会形成“竞速”——谁先用旧 token 换新，另一个手里的就作废，而服务端能检测到“同一个旧 token 被用了两次”，立刻判定被盗并吊销整条 token 链，强制重新登录。这就是现代持久登录“被盗可止损”的关键。JWT 方案里通常拆成短命的 access_token（几分钟）和长命的 refresh_token（几天），兼顾安全和体验。

“记住我”该不该勾

  • 私人设备：放心勾：只有你能解锁的手机和电脑，勾上省去每天输密码
  • 公共/他人设备：绝不勾：网吧、公司公用机、朋友电脑——勾了等于把账号送人
  • 拿不准时：不勾 + 用密码管理器：让密码管理器替你填账号密码，省事和安全兼得
  1. 先判断：这台设备离开你的视线后，别人能直接打开用吗？
  2. 只有你能用的设备→勾；否则→不勾，就这么简单
  3. 在网吧或朋友电脑登录过，走之前务必点“退出登录”（只关页面不算）
  4. 定期去账号设置的“已登录设备”里看看，把不认识的设备踢下线
  5. 手机丢了：第一时间用“查找设备”远程锁定，并去重要网站改密码
