直连与链式代理

你的请求，中间转了几道手？
👀 日常场景

你在公司内网打不开某个技术论坛，回家用自己网络却能打开；做跨境电商的朋友，电脑上总挂着个“代理”，访问国外网站飞快——同一个网址，走的路不一样，结果完全不同。直连、代理、代理套代理，到底差在哪？

原理：它是怎么运作的

💡 直连是浏览器直达目标服务器；代理是中间加一道“跑腿”；链式代理是多道跑腿接力，每一跳只知道相邻两跳，层层隐藏真实起点。

先看全过程

  1. 直连：浏览器直接向目标服务器发请求
  2. 目标看到的 IP 就是你的真实 IP
  3. 单代理：请求先发给代理服务器
  4. 代理代你转发，目标只看到代理的 IP
  5. 链式代理：代理 1 把请求转给代理 2
  6. 代理 2 再转给目标，每跳只知上下游

先分清两个“代理”：正向代理是帮“客户端”跑腿的（你主动配置，替你去拿资源，隐藏你的身份）；反向代理是帮“服务端”看门的（Nginx 那种，替网站挡流量、做负载均衡，用户无感知）。这里说的是正向代理。

直连最快、链路最短，但你的真实 IP 会暴露给目标服务器，且受本地网络限制（公司网、校园网常有白名单）。单代理解决两个问题：隐藏真实 IP（目标只看到代理的出口 IP），以及绕过本地限制（只要你能连上代理、代理能连上目标就行）——俗称“翻墙”的本质就是这个。

链式代理是“代理套代理”：请求经过代理 1 → 代理 2 → … → 目标。关键设计是每一跳只知道它的上一跳和下一跳，不知道完整链条。代理 2 知道请求来自代理 1，但不知道最初是你发的。这就是 Tor（三层洋葱路由）的核心思想，只是 Tor 还给每层加了加密，叫“洋葱”（层层剥开）。代价也很直白：每多一跳就多一份延迟，链越长越慢；而且链条末端（出口节点）如果走的是明文 http，它能看到你的原始内容——HTTPS 依然是最后一道防线。

我该怎么用代理

  • 只给浏览器配：浏览器设置或 SwitchyOmega 这类插件里填代理，最轻量
  • 给整台电脑配：系统设置 → 网络 → 代理里填，走系统代理的软件都生效
  • 用 Clash 这类规则客户端：按规则自动分流，国内外网站各走各的路
  1. 先想清楚：只是浏览器用，还是整台电脑用
  2. 拿到代理信息：地址（IP 或域名）、端口、账号密码（如果有）
  3. 只浏览器用→在浏览器/插件的代理设置里填进去；整台电脑→在系统网络设置里填
  4. 打开 ip.sb 这类“看我 IP”的网站，确认显示的不再是你的真实 IP
  5. 不用的时候记得关掉：代理一挂，所有流量都跟着断
