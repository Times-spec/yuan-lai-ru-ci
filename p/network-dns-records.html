DNS：网址的电话簿

你输入的每个网址，都要先问它
👀 日常场景

你在浏览器输入 www.example.com 回车，页面打开了。但浏览器一开始根本不知道服务器在哪——它得先问 DNS 要 IP，几十毫秒内问答完成，而每条解析记录（A、CNAME、MX……）都在 DNS 控制台里静静躺着。

原理：它是怎么运作的

💡 DNS 是互联网的“电话本”，把域名翻译成 IP；A/CNAME/MX/TXT 等记录类型是电话本里不同用途的字段。

先看全过程

  1. 浏览器输入域名，先查本地缓存
  2. 缓存未中，请求运营商递归解析器
  3. 递归器问根服务器：.com 归谁管
  4. 再问顶级域服务器：要权威服务器地址
  5. 权威服务器返回该域名的 IP 记录
  6. 浏览器拿到 IP，缓存并建连访问

DNS（域名系统）是互联网的“电话本”：人记域名，机器只认 IP，DNS 负责在两者之间翻译。

一次完整的解析是“递归+迭代”接力：浏览器先查本地缓存，没有就问运营商的递归解析器；递归解析器从根服务器问起（“.”根只知道 .com 归谁管），再问 .com 的顶级域服务器（它知道 example.com 的权威服务器是谁），最后问 example.com 的权威服务器要答案，层层拿到 IP 后缓存起来，下次直接用。

记录类型就是电话本里的不同“字段”：A 记录存 IPv4 地址、AAAA 存 IPv6 地址，是最常用的两条；CNAME 是别名（www.example.com 指向 example.com，改 IP 只改一处）；MX 告诉全世界“这个域名的邮件该投递到哪台服务器”；TXT 存任意文本，常用来放域名所有权验证码和 SPF/DKIM 反垃圾邮件配置；NS 则声明“这个子域的解析权交给谁”。TTL（生存时间）决定一条记录能被缓存多久，是“改解析多久生效”的总开关。

🌀 如果没有它会怎样

没有 DNS，你得背下每个网站的 IP 地址才能上网；网站一换服务器，全世界都要更新自己的「通讯录」。域名本质上是给机器地址起的人话名字。

🚫 常见误解

改完解析，全世界立刻就能生效。其实各级缓存都按 TTL 存着旧记录：TTL 没过期之前，这次改动对一部分人来说就是还没发生。

想深入了解怎么办

  • 动手派：dig 命令：一条命令看穿 A/MX/TXT，比看十页文档直观
  • 系统派：经典教材：《计算机网络：自顶向下方法》的 DNS 章节，递归迭代讲得最透
  • 实战派：买个域名：几十块钱买个域名，亲手配 A/CNAME/MX/TXT 记录
  1. 先玩 dig：`dig example.com A`、`dig example.com MX`，看不同记录长什么样
  2. 用 `dig +trace` 跟一次从根服务器开始的完整解析，看“接力”过程
  3. 读《自顶向下》DNS 章节：递归 vs 迭代、缓存、TTL 一次搞懂
  4. 买个便宜域名，在 DNS 控制台亲手加 A、CNAME、TXT 记录
  5. 故意配错一次（比如 TTL 设超大再改 IP），体会“改解析多久生效”
  6. 进阶：了解 DNSSEC 是怎么防伪造的，DoH 又解决了什么
