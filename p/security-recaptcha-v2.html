reCAPTCHA v2「我不是机器人」

勾一下的背后，是一整套行为审讯
👀 日常场景

提交表单前，一个小方框写着“我不是机器人”，你点一下打上勾，页面直接通过了。但有时候点完勾，它却弹出一堆图片让你选。你不禁想：我就点了个勾，它凭什么断定我是人？

原理：它是怎么运作的

💡 一次点击触发的风险评估：低风险直接放行，高风险才出图片题。

先看全过程

  1. 页面加载时 SDK 静默采集环境信号
  2. 用户点击复选框的瞬间记录行为
  3. 分析鼠标轨迹、时序、Cookie 历史
  4. 低风险：直接打勾通过
  5. 高风险：弹出图片/音频挑战
  6. 后端二次校验 token 才算数

那个复选框是个“诱饵”：真正的验证在点击发生的前后就已经完成了。reCAPTCHA 的 JS 在页面加载后会静默采集信号——鼠标在页面上的移动轨迹、浏览器指纹、时区语言、屏幕参数，以及最重要的：这个浏览器过去在 Google 生态里的 Cookie 历史（一个养了很久、行为正常的 Google 账号，天然就是低风险信号）。当你点击复选框时，系统分析点击的时序特征：真人从看到框到点击有反应延迟，点击位置落在框内随机处；脚本则是零延迟、坐标精准。综合评分低风险就直接通过；高风险才弹出图片挑战做二次确认。最后前端拿到的 token 必须由你的后端调用 siteverify 接口二次校验——因为前端的一切都可伪造，只有 Google 服务器说了算。国内站点注意把 google.com 换成 recaptcha.net 域名，否则国内用户根本加载不出来。

网站该如何接入

  • Google reCAPTCHA v2 Checkbox：最经典的复选框验证，文档和生态最全。
  • Cloudflare Turnstile：Cloudflare 出品的无感/轻量替代，隐私更友好。
  • hCaptcha：功能对标的替代品，支持中文和奖励机制。
  1. 在 Google reCAPTCHA 后台注册站点，拿到 site key 和 secret key。
  2. 前端引入 api.js，用 grecaptcha.render 渲染复选框组件。
  3. 用户通过验证后，前端拿到一次性 token（g-recaptcha-response）。
  4. 表单提交时把 token 一起发给自己后端。
  5. 后端用 secret key 调 siteverify 接口校验 token 的有效性和时间戳。
  6. 校验成功才执行业务；国内站点把接口域名换成 www.recaptcha.net。
