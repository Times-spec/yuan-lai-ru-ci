策略组：自动选最快节点

手动挡、自动挡、四驱，任你挑选
👀 日常场景

代理页面里躺着一堆分组：节点选择、自动选择、故障转移、负载均衡……每个都能点，但点了有什么区别？选错了，轻则网速打折，重则视频看到一半卡住、游戏掉线。

原理：它是怎么运作的

💡 策略组 = 一组节点 + 一种挑选策略：手动指定、自动测速选最快、故障时自动切换、把流量打散分摊。

先看全过程

  1. 规则命中了某个策略组
  2. select：用你手动选中的节点
  3. url-test：定期测速，自动切延迟最低的
  4. fallback：按顺序试，坏了换下一个
  5. load-balance：把连接分散到多个节点

一个个说。select 是“手动挡”：组里列出一堆节点，你点哪个就用哪个，所见即所得，日常主力。url-test 是“自动挡”：按你设定的间隔（interval）自动测速，永远用延迟最低的那个，适合懒人，代价是后台测速会消耗一点点流量。fallback 是“备胎制”：按你排的顺序依次尝试，第一个挂了自动顺延到下一个，直播、开会这种求稳场景最爱它。load-balance 是“分摊制”：按策略（比如轮询）把连接打散到多个节点，大文件下载能跑满带宽，但同一会话的出口 IP 会跳变，有些网站会判定异常而触发风控，看视频、登录账号时慎用。

策略组还可以嵌套：组的成员可以是另一个组，比如“国外网站”组里引用“自动选择”组，层层调度。

怎么选？记住：日常用手动，懒人用自动测速，求稳用故障转移，下载用负载均衡。没有银弹，只有 trade-off（权衡）。

策略组怎么配

  • select 手动选择：组里列节点，你点哪个用哪个，所见即所得
  • url-test 自动测速：按间隔自动测延迟，永远用最快的
  • fallback 故障转移：按顺序排备胎，挂了自动顺延
  • load-balance 负载均衡：把连接打散到多个节点，下载跑满带宽
  1. 先定目标：求稳、求快，还是求省心
  2. 日常：建一个 select 组，手动选延迟最低的节点
  3. 懒人：建 url-test 组，测速间隔设 300 秒以上（别太短，费流量）
  4. 重要场合前：切到 fallback 组，把备胎顺序排好
  5. 下载大文件：可以试 load-balance，但别拿它登录账号
  6. 进阶：组里可以嵌套组，比如“国外网站”组引用“自动选择”组
