HSTS：强制全站 HTTPS

告诉浏览器：以后只许走加密通道
👀 日常场景

你在咖啡馆连公共 Wi-Fi 打开银行网站，明明输入的是 http，浏览器却自动变成了 https，而且不让你改回去。这就是 HSTS 在保护你：它让浏览器记住“这个站只许用 https 访问”。

原理：它是怎么运作的

💡 网站通过 Strict-Transport-Security 响应头告诉浏览器：未来一段时间内，这个域名只许用 HTTPS 访问，浏览器会自动把 http 升级成 https。

先看全过程

  1. 用户首次用 HTTPS 访问网站
  2. 服务器返回 HSTS 响应头
  3. 浏览器记住该域名只许 HTTPS
  4. 之后敲 http 也被强制转 https
  5. 证书无效时浏览器直接拒绝访问

HSTS 是网站给浏览器下的一道“死命令”：响应头 Strict-Transport-Security 告诉浏览器，“未来 N 秒内，这个域名只许用 HTTPS 访问”。浏览器记住后，即使用户手动敲 http，浏览器也会在本地直接升级成 https 再发请求，连服务器都不问。它的存在是为了堵住 SSL 剥离攻击——攻击者在公共 Wi-Fi 上把“跳 https”的 301 拦截掉，让用户全程走明文 http；有了 HSTS，浏览器根本不给攻击者这个机会。代价是“说出去的话收不回”：一旦开启，在 max-age 过期前，证书配错或过期会导致网站彻底打不开，连临时放行都不行。所以上线姿势是先用短 max-age 灰度，确认全站 HTTPS 无死角后再加到一年、加上 includeSubDomains。银行、政务这类站点还会申请加入浏览器的 HSTS Preload 内置名单，连第一次访问都受到保护。

开发者：应该如何接入

  • Nginx 响应头：add_header 一行配置
  • CDN 一键开启：Cloudflare、阿里云 CDN 控制台开关
  • HSTS Preload：提交到 hstspreload.org，进浏览器内置名单
  1. 全站确认 HTTPS 可用，证书链完整
  2. 先用较短的 max-age（如 1 天）灰度验证
  3. 在 Nginx 或网关加 Strict-Transport-Security 响应头
  4. 确认无误后把 max-age 加到 1 年，加 includeSubDomains
  5. 高安全站点可申请加入 HSTS Preload 名单
