reCAPTCHA v3 无感知评分

全程无弹窗，它在后台给你打了个分
👀 日常场景

有些网站登录注册全程没有任何验证码弹窗，你点提交就直接进去了。但你不知道的是：在你浏览页面的每一秒，都有个看不见的考官在观察你的行为，最后给你打了个 0 到 1 的分数，决定放不放你过。

原理：它是怎么运作的

💡 不打扰用户，后台持续采集行为信号，为每次请求打出 0.0–1.0 的风险分。

先看全过程

  1. 页面加载即运行 JS 静默采集
  2. 监控鼠标、滚动、点击等交互
  3. 用户操作时生成一次性 token
  4. token 随请求发给后端
  5. 后端调接口查询该 token 的评分
  6. 按业务阈值决定放行或加验

v3 把验证从“考试”变成了“监考”：页面一加载，JS 就开始记录你的行为——鼠标怎么动、滚轮怎么滑、在输入框停留多久、页面停留总时长。这些信号被发到 Google，结合这个浏览器/IP 的历史信誉，用模型打出一个 0.0（极可能是机器人）到 1.0（极可能是真人）的分数。关键设计是：Google 不替你决定，只给分数；阈值由网站自己定——登录可以设 0.5，支付可以设 0.7，低于阈值就触发短信验证或直接拦截。每次用户做关键操作（提交表单）时，前端调用 grecaptcha.execute 拿一个一次性 token，后端拿 token 去查分。分数是和具体动作（action）绑定的，比如 login 和 checkout 可以设不同阈值。这种设计的代价是误伤：行为古怪的真人（比如用无障碍工具、网速极慢）可能被打低分，所以阈值调优和降级方案是接入 v3 的核心功课。

网站该如何接入

  • Google reCAPTCHA v3：无感评分的鼻祖，按 action 区分场景打分。
  • Cloudflare Turnstile（Non-Interactive）：Cloudflare 的无交互模式，接入更轻。
  • hCaptcha（被动模式）：hCaptcha 的无感评分能力。
  1. 在 reCAPTCHA 后台注册 v3 站点，拿到 site key 和 secret key。
  2. 前端引入 api.js，关键操作前调用 grecaptcha.execute(siteKey, {action: 'login'})。
  3. 把返回的 token 随业务请求发给后端（token 两分钟内有效）。
  4. 后端调 siteverify 接口，用 secret key 查询该 token 的 score 和 action。
  5. 核对 action 与当前业务一致，按预设阈值（如 login≥0.5）决定放行/加验/拦截。
  6. 上线后持续观察分数分布，逐步调优各 action 的阈值。
