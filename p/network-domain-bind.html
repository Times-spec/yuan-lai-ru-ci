域名绑定网站：买完域名然后呢

两边都要配：DNS 指路，服务端认领
👀 日常场景

你买了个心仪的域名，想让它打开你的网站。在 DNS 控制台点下“添加记录”，面对主机记录、记录类型、记录值一脸懵；好不容易填完，打开还是一片空白——因为绑定域名的工作只做了一半，另一半在网站那边。

原理：它是怎么运作的

💡 绑定域名要做两件事：DNS 告诉全世界“这个域名去哪”，服务端说“我认这个域名”；两边对上，网站才能访问。

先看全过程

  1. 域名只是名字，访问要靠 IP
  2. DNS 记录 = 名字的指向标
  3. A 记录：裸域名 → 服务器 IP
  4. CNAME：子域名 → 另一个域名
  5. 服务端也要“认领”这个域名
  6. 对上之后，HTTPS 证书跟上

为什么配了 DNS 还是打不开？因为绑定域名是“两边”的事。

第一边在域名这边：DNS 只管“指路”。你在控制台加的每条记录，都是一句“这个名字去哪找”：A 记录说“裸域名去这个 IP”，CNAME 说“这个子域名去问另一个名字”。全世界的 DNS 服务器照着指路，用户才能找到你的服务器。

第二边在网站这边：服务器要“认领”。互联网上无数网站共用平台（比如 Vercel 上跑着几十万个站），光找到服务器不够，服务器还要知道“这个域名是我的”。所以 Vercel 要在项目里加域名，云服务器要在 Nginx 里写 server_name——都是认领动作。

共性就一句话：DNS 指路 + 服务端认领。Vercel 把后半段做成了点点鼠标（还顺手把 HTTPS 证书办了）；云服务器则要自己动手：A 记录指到公网 IP，Nginx 配好 server_name，再申请证书。

本站就是活例子：www.aha.voyager06.tech 一条 CNAME 指向 cname.vercel-dns.com，Vercel 项目里加上域名，几分钟后 https 就通了。

我该怎么绑定域名

  • 托管平台（如 Vercel）：子域名 CNAME 指向平台地址，再在项目设置里加上域名，证书自动办好
  • 云服务器（ECS）：A 记录指向服务器公网 IP，Nginx 里配置 server_name 认领域名
  • 裸域名 vs 子域名：裸域名（@）用 A 记录指 IP，子域名（www）用 CNAME
  1. 想好要绑定的完整域名，如 www.aha.voyager06.tech
  2. 去 DNS 控制台添加记录：平台用 CNAME，云服务器用 A
  3. 去服务端认领：Vercel 项目加域名 / Nginx 写 server_name
  4. 等几分钟让 DNS 生效，浏览器访问验证
  5. 确认 https 小锁头正常（Vercel 自动，云服务器需配证书）
