HTTP 301 永久重定向

这个地址永久搬家了，以后直接去新地址
👀 日常场景

你收藏的博客换了新域名，打开旧网址却瞬间跳到了新站；随手敲了 http:// 开头，浏览器自动变成了 https://。这些“自动转场”的背后就是 301：网站在告诉浏览器和搜索引擎，这个页面永久搬家了。

原理：它是怎么运作的

💡 服务端返回 301 状态码加 Location 头，告诉浏览器“这个资源永久搬到新地址了”，浏览器会自动请求新地址，并把这条映射记下来。

先看全过程

  1. 浏览器请求旧地址
  2. 服务器返回 301 和新地址
  3. 浏览器自动请求新地址
  4. 浏览器缓存这条映射
  5. 搜索引擎把权重转给新地址

当浏览器请求一个地址，服务器可以在响应里只回一个 301 状态码和一个 Location 头，意思是“你要的东西永久搬到这个新地址了”。浏览器收到后会自动再发一次请求去新地址，地址栏也随之更新，整个过程快到你几乎无感。301 的精髓在“永久”二字：浏览器会把“旧地址→新地址”的映射缓存下来（有的浏览器缓存时间极长），下次你再访问旧地址，浏览器连服务器都不问就直接跳过去；搜索引擎也会把旧页面的排名权重转移给新页面。这正是网站换域名、http 全站切 https、统一网址末尾斜杠时用它的原因。但“永久”也是把双刃剑：一旦配错，想撤回时用户浏览器里的缓存还在生效，只能等缓存过期或引导用户清缓存。所以 301 上线前一定要用 curl -I 反复验证，确认返回码和 Location 都正确。顺带一提：301 对 POST 请求的历史行为是改成 GET 再发，这也是后来有了 307/308 的原因之一。

🌀 如果没有它会怎样

没有 301，网站换域名就等于推倒重来：老链接全部变成 404，搜索引擎攒下的权重清零，用户收藏的书签集体失效。

🚫 常见误解

301 配错了，改回服务器配置就行。其实浏览器会长期缓存这条映射：你改了服务器，老访客的浏览器还照着旧映射跳，不清缓存就不会恢复。

服务端该怎么配

  • Nginx return 指令：一行配置即可完成跳转，性能最好
  • Web 框架 redirect：Express、Django 等框架都有内置的 redirect 方法
  • CDN 边缘规则：在 CDN 控制台配重定向规则，不碰源站代码
  1. 确认是永久搬迁（域名更换、http→https）才用 301，临时活动页用 302
  2. 在 Nginx 的 server 块里写 return 301 新地址，保留原路径与查询参数
  3. 用 curl -I 旧地址检查返回码是否为 301、Location 是否正确
  4. 更新站内链接和 sitemap，避免留下跳转链
  5. 到搜索引擎站长平台提交改版或换域名规则
