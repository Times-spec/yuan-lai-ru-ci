设备指纹

清掉 Cookie 也甩不掉的隐形身份证
👀 日常场景

换了个新手机登录银行 App，立刻被要求额外验证；某平台薅羊毛被封号，换账号、清缓存、开无痕都没用，平台还是认出了“这是同一台设备”。它到底靠什么认出你的？——靠的根本不是 Cookie，而是一组你删不掉的设备特征。

原理：它是怎么运作的

💡 采集数十维软硬件特征哈希成唯一 ID，无状态识别设备，Cookie 清了也认得。

先看全过程

  1. JS 采集 UA、分辨率、时区、语言
  2. 采集字体列表、插件、Canvas 渲染特征
  3. WebGL 指纹：显卡渲染的像素级差异
  4. 数十维信号拼接后哈希成指纹 ID
  5. 服务端比对历史指纹库做风控
  6. 移动端叠加传感器偏差、系统 ID

设备指纹玩的是“无状态识别”：不靠存在你设备上的任何东西（Cookie、localStorage 都可以清掉），而是靠设备“与生俱来”的特征组合。浏览器会暴露大量信号：User-Agent、屏幕分辨率、时区、系统语言、已安装字体列表、Canvas 画布渲染的像素差异（同一张图在不同显卡驱动下渲染出的像素有细微差别）、WebGL 渲染器字符串、音频指纹等。单个信号都不唯一，但几十维组合起来，EFF（电子前哨基金会）实测能达到约 18.1 比特的熵——意味着在几十万台设备里基本能精准定位一台。移动端还能用加速度计/陀螺仪的硬件偏差、IDFV（苹果）/AAID（安卓）增强。攻防的关键在于：指纹是“概率性识别”而非“确定性 ID”，浏览器升级、换显卡都会让指纹漂移，所以风控系统用的是相似度匹配而非精确匹配；对抗方则用指纹浏览器（批量伪造环境）来反制。这也是为什么它主要用于风控（识别羊毛党、撞库），而不是当登录凭证用。

网站是怎么做到的

  • 浏览器端信号采集：用 JS 静默收集几十维特征：分辨率、字体、Canvas 渲染差异等
  • 服务端关联分析：把指纹和账号、IP、行为拼成“设备-账号”关系图谱
  • 第三方风控服务：数美、同盾这类厂商把指纹采集+风险画像打包成服务
  1. 用户打开登录/注册页，前端 JS 在后台静默采集设备特征
  2. 几十维特征哈希成一个指纹 ID，随登录请求一起发给服务端
  3. 服务端把“指纹-账号-IP-时间”存成关联记录，攒成设备画像
  4. 新账号用同一指纹短时间注册/登录多个账号→标记羊毛党
  5. 老账号突然换指纹+异地→触发升级验证（短信/人脸）
  6. 定期更新采集算法：浏览器一升级指纹就漂移，算法要跟上
