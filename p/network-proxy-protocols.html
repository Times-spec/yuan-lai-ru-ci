翻墙协议：谁在看你翻墙

协议是衣服，监测看的是身形
👀 日常场景

Shadowsocks、VLESS、Trojan、Hysteria……协议名字越出越多，商家都说自己“抗封锁最强”。但换协议真的能隐身吗？先搞清一个问题：到底是谁、在看什么。

原理：它是怎么运作的

💡 协议决定流量“长什么样”；能监测你的有四方：GFW 看流量特征，网站看 IP 和 TLS 指纹，机场主看域名，本地网管看 SNI。

先看全过程

  1. 协议=流量伪装术
  2. GFW：看 SNI 和流量指纹
  3. 网站：看 IP 信誉+JA3 指纹
  4. 机场主：能看到你访问的域名
  5. 本地网管：同样看 SNI
  6. 没有任何协议能“隐身”

协议速览，一句话版：Shadowsocks 是老牌轻量选手，简单快速但特征明显；VMess 是 V2Ray 系的多面手；VLESS 是更轻量的继任者；Trojan 把流量伪装成正常 HTTPS；Hysteria2 基于 QUIC，弱网提速明显；WireGuard 是正经 VPN 协议，速度快但特征也明显。

核心洞察：协议只能改变“流量长什么样”，不能让你“不存在”。四方监测各看各的：GFW 看 SNI（你连了哪个域名）、流量指纹和主动探测——这就是它能封锁协议的原因；网站看 IP 信誉库和 TLS 指纹，截图里的 JA3/JA4 就是干这个的：不同客户端的 TLS 握手特征各不相同；机场/节点主能看到你的 DNS 和 SNI，也就是你访问了哪些域名（除非用上加密 DNS 和 ECH）；公司、校园网的网管同理。

所以“抗封锁”不等于“匿名”。选协议之前，先想清楚你的威胁模型：你要防的到底是谁。

怎么少暴露一点

  • 选新协议：VLESS/Trojan/Hysteria2 的流量更像正常 HTTPS，比老协议难识别
  • 堵住 DNS 和 WebRTC 泄露：开 TUN 模式让 DNS 也走代理，堵 WebRTC 见前一篇
  • 接受现实：没有隐身衣：机场主和审查层面，流量存在本身就可见
  1. 想清楚你要防谁：网站、网管，还是审查
  2. 按需选协议：日常用 VLESS/Trojan 类
  3. 开 TUN 模式，让 DNS 也走代理
  4. 堵 WebRTC 泄露（见 WebRTC 那篇）
  5. 记住：机场主始终能看到你的域名
