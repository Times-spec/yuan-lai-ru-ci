第三方 OAuth 登录

“用微信登录”时，网站全程没碰过你的密码
👀 日常场景

点“使用微信登录”，页面跳到微信、你点同意授权，再跳回原来的网站，直接就是登录态了。你输入密码了吗？没有。那这个网站是怎么确认“你就是你”的？整个过程里，它从头到尾没见过你的密码。

原理：它是怎么运作的

💡 OAuth 2.0 授权码流程：网站拿“授权码”换“令牌”，全程不接触用户密码。

先看全过程

  1. 网站把用户送往第三方授权页
  2. 用户在第三方站点登录并点同意
  3. 第三方带授权码 code 跳回网站
  4. 后端用 code 换取 access_token
  5. 用 token 向第三方拉取用户信息
  6. 网站据此创建/登录本地账号

OAuth 2.0 解决的核心问题是“委托而不交钥匙”：你想让 A 网站知道“我是微信用户张三”，但不想把微信密码告诉 A。标准授权码流程分四步：A 网站把你重定向到微信授权页（带上 client_id 和 redirect_uri）；你在微信的地盘登录并点“同意”；微信带一个一次性授权码（code）把你送回 A 网站的回调地址；A 网站的后端拿 code + 自己的 client_secret 去微信换 access_token（令牌），再用令牌拉取你的昵称头像。这里有两个安全关键：一是 code 只能用一次、几分钟过期，且换 token 必须走后端（secret 不能暴露给前端）；二是 redirect_uri 必须在第三方后台精确报备，防止授权码被发到攻击者的网站。整个流程里你的密码只在微信输入过一次，A 网站拿到的是“微信盖过章的身份证明”，这就是为什么注销 A 网站账号不影响微信账号——两者密码体系完全隔离。

网站该如何实现

  • 微信开放平台（网站应用）：国内最刚需的第三方登录，需申请网站应用资质。
  • Sign in with Apple / Google Identity：苹果和谷歌的官方登录，海外合规友好。
  • GitHub OAuth：开发者社区标配，接入文档极简。
  • Auth0 / Keycloak：统一聚合多种登录方式的身份中台。
  1. 在第三方开放平台创建应用，配置授权回调域 redirect_uri，拿到 client_id/secret。
  2. 前端“用 XX 登录”按钮跳转到第三方授权地址，带上 state 防 CSRF（随机串存 session）。
  3. 用户同意后跳回你的回调地址，带回 code 和 state。
  4. 后端先校验 state 一致，再用 code+client_secret 调 token 接口换 access_token。
  5. 用 access_token 拉取用户唯一标识（如 openid）和基本资料。
  6. 按 openid 查找或创建本地账号，写入自己站点的登录会话。
