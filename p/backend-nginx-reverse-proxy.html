Nginx 反向代理

所有请求，先过它这一关
👀 日常场景

你在浏览器输入网址，请求并没有直达写业务代码的那台服务器，而是先被 Nginx 接住：它负责 HTTPS 加密、把静态图片直接返回、再把动态请求转发给真正的应用。Nginx 就像公司前台——客人先到前台，再被领到对的办公室。

原理：它是怎么运作的

💡 挡在应用服务器前面，统一处理 HTTPS、静态文件、转发与限流的流量网关。

先看全过程

  1. 客户端请求打到 Nginx
  2. Nginx 完成 TLS 握手解密
  3. 静态资源直接从磁盘返回
  4. 动态请求按规则转发后端
  5. 补上真实 IP 等请求头
  6. 拿到后端响应返回客户端

「反向」是相对「正向」代理而言的：正向代理是替客户端上网（比如梯子），反向代理是替服务端接客——客户端以为自己在和 Nginx 说话，背后真正干活的可能是 Node、Java 或 Python 服务。

Nginx 能扛高并发，靠的是事件驱动模型：一个 worker 进程用 epoll 同时盯着上万个连接，连接空闲时不占线程，数据来了才处理。对比传统「一个连接一个线程」的 Apache，内存占用低一个数量级，这也是它成为默认网关的原因。

网关层的价值在于「后端不用重复造轮子」：HTTPS 证书只在 Nginx 上配一次（SSL 卸载），静态文件走 sendfile 零拷贝直接返回，慢请求在这里做限流和超时熔断。proxy_set_header 透传 X-Real-IP 很关键——否则后端看到的客户端 IP 全是 Nginx 自己，限流、风控都会错乱。

开发者：应该如何接入

  • Nginx：C 语言编写的老牌高性能网关，资源占用极低
  • Caddy：自动申请续期 HTTPS 证书，配置极简
  • Traefik：云原生网关，自动发现容器服务
  1. 安装 Nginx，确认能打开默认欢迎页
  2. 写 server 块监听 80/443，配好域名和证书
  3. location / 下用 proxy_pass 转发到应用端口
  4. 加上 proxy_set_header 透传 Host 和真实 IP
  5. 静态目录用 root/alias 直接返回，加 expires 缓存头
  6. nginx -t 检查语法，reload 平滑生效
