SSH：安全连上远程服务器

私钥从不出门，也能证明你就是你
👀 日常场景

程序员打开终端，敲下 ssh root@云服务器IP，输一次密钥口令就进去了；Git push 走的也是 SSH，不用每次输密码。第一次连接时，终端还会较真地问：服务器指纹对吗？这套流程是互联网上最常用的远程管理方式。

原理：它是怎么运作的

💡 非对称加密的挑战应答：服务端用你的公钥加密一个随机数，只有持有私钥的你能解开，从而证明身份——私钥从不传输。

先看全过程

  1. 本地生成密钥对（公钥+私钥）
  2. 公钥写入服务器 authorized_keys
  3. 发起连接，先协商会话加密
  4. 服务端发来随机数挑战
  5. 本地用私钥签名后发回
  6. 服务端验签通过，登录成功

SSH 要解决的问题很原始：怎么通过不安全的网络，安全地操作另一台机器。早年用 Telnet，账号密码明文传输，中间抓个包就全看见了。SSH 先加密再说话：协商出只有双方知道的会话密钥，之后传输全加密。

登录用的是非对称加密的“挑战应答”：公钥（锁）放在服务器的 ~/.ssh/authorized_keys 里，私钥（钥匙）只存在你自己电脑上，绝不传输。登录时服务端生成随机数，用你的公钥加密发给你；只有你的私钥能解开，你签名发回，服务端验签通过，就知道“对面确实是私钥持有者”。

为什么比密码安全？密码注定熵低：会被撞库、钓鱼、键盘记录，还可能多站复用。一把 ed25519 密钥暴力破解在物理上不可行，私钥文件还能再加一层口令加密。

第一次连接的指纹确认防的是中间人攻击：SSH 用 TOFU 模型，第一次把服务器公钥指纹记进 ~/.ssh/known_hosts，以后每次比对——指纹变了就直接拒绝并警告。随手敲 yes 等于白做；正确做法是去云厂商控制台核对。

它同时是 Git over SSH、Ansible、VS Code Remote 的底层通道。

第一次用 SSH

  • macOS / Linux 自带终端：开箱就有 ssh 命令，不用装任何东西
  • Windows Terminal：Win10/11 自带 OpenSSH，终端里直接敲 ssh
  • 手机端：Termius：手机上也能连服务器，应急排障
  1. 打开终端，敲 `ssh 用户名@服务器IP`（云厂商给的，如 `ssh root@1.2.3.4`）
  2. 第一次会问“指纹对吗”：先去云厂商控制台核对指纹，确认无误再敲 yes
  3. 输入密码（输入时屏幕没反应是正常的，输完回车）
  4. 进去后先生成密钥：`ssh-keygen -t ed25519`，一路回车
  5. `ssh-copy-id -i ~/.ssh/id_ed25519.pub 用户名@服务器IP`，把公钥送上去
  6. 以后再连就不用输密码了（如果设了密钥口令，只输那一次）
