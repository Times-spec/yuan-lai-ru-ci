Docker Compose：一键启动整套服务

一条命令，拉起整个开发环境
👀 日常场景

新同事入职第一天，配环境配到怀疑人生：先装 MySQL，再装 Redis，还调 Node 版本。Docker Compose 用一个 YAML 文件声明所有服务，一条 up 命令就把数据库、缓存、应用全拉起来——环境配置从此有了「说明书」。

原理：它是怎么运作的

💡 用 YAML 声明多容器应用的服务、网络与卷，一条命令编排启停。

先看全过程

  1. 编写 compose.yaml 声明服务
  2. 定义服务间的依赖与网络
  3. 挂载卷持久化数据
  4. docker compose up 一键启动
  5. 各服务通过服务名互访
  6. docker compose down 清理

单个容器好管，一堆容器就乱了：Web 应用依赖 MySQL 和 Redis，启动有先后，网络要互通，数据要持久化。Compose 就是这套「多容器说明书」：一个 YAML 文件里声明每个服务用什么镜像、暴露什么端口、挂什么卷、依赖谁，Compose 按依赖顺序拉起，还自动建好内部网络——服务之间直接用服务名当主机名互相访问，不用记 IP。

它和 K8s 的分工很明确：Compose 管开发和测试环境的「一键还原」，K8s 管生产的「大规模调度」。Compose 的卷（volume）解决数据持久化：容器删了重建，MySQL 的数据还在。环境变量和 .env 文件让同一份 compose 文件能在开发、测试间复用。

注意 Compose 不做高可用：服务挂了它只会按 restart 策略重启本机容器，不会跨机器调度。生产环境要扩缩容、滚动更新，还是得上 K8s 或云托管服务。

开发者：应该如何接入

  • Docker Compose：官方编排工具，单机多容器
  • Kubernetes：生产级容器编排，自动扩缩容
  • Podman Compose：Podman 生态的兼容实现
  1. 在项目根目录创建 compose.yaml
  2. 声明 app、db、redis 三个服务及镜像版本
  3. 用 volumes 给数据库挂载数据卷
  4. 用 depends_on 声明启动依赖顺序
  5. 敏感配置放 .env 文件，不进版本库
  6. docker compose up -d 启动，logs -f 看日志
