DOH：加密的 DNS 查询

把查域名的请求，装进加密信封
👀 日常场景

你在咖啡馆连公共 Wi-Fi，搜了些“不想让别人知道”的东西。网页是 HTTPS 加密的，但“你访问了哪些域名”在传统 DNS 下是明文广播的——Wi-Fi 主人、运营商都能看到完整清单。DOH 就是来堵这个漏洞的。

原理：它是怎么运作的

💡 把 DNS 查询装进 HTTPS 请求里走 443 端口传输，中间人既看不到查了什么域名，也篡改不了答案。

先看全过程

  1. 应用要解析域名，准备发起查询
  2. 传统方式：明文 DNS 走 53 端口发出
  3. 同一 Wi-Fi 下的旁观者能直接看到域名
  4. DOH：把查询封装进 HTTPS 请求
  5. 走 443 端口，混在普通网页流量中
  6. 解析器解密查询，加密返回答案

传统 DNS 生于 1983 年，那时没人考虑隐私：查询和应答都是明文 UDP，走 53 端口。同一网络下的任何人都能看到你在查哪些域名（虽然看不到具体看了什么页面，但域名本身信息量极大），还能伪造应答把你劫持到钓鱼站——这就是“DNS 劫持”。

DOH（RFC 8484）的做法很巧妙：不发明新端口、不发明新加密，直接把 DNS 查询塞进 HTTPS 请求里。走的是 443 端口，和普通网页流量长得一模一样，中间设备既难以识别、更难以封锁（封了 443 等于断网）。查询内容被 TLS 加密，只有你和你信任的解析器能看到。

代价也有：DNS 查询本来走 UDP 一去一回极快，套上 TCP+TLS 握手后延迟略增（通常有连接复用，影响不大）；争议在于它绕过了运营商/企业的本地 DNS 策略——家长控制、公司内网域名、企业审计可能因此失效。所以浏览器一般允许你手动开关 DoH，它解决的是“防偷窥”，不是“防解析器本身”——你信任的解析器依然知道一切。

我该怎么开启 DOH

  • Chrome / Edge：设置 → 隐私和安全 → 安全 DNS，开启后选 Cloudflare 或 Google
  • Firefox：设置 → 隐私与安全 → 启用 DNS over HTTPS，选默认或自定义
  • 手机全局：安卓私人 DNS：设置 → 网络 → 私人 DNS，填 one.one.one.one，全手机生效
  1. 打开浏览器设置，搜索“DNS”，找到“安全 DNS / 加密 DNS”开关
  2. 打开它，选择 Cloudflare（1.1.1.1）或 Google（8.8.8.8）
  3. 去 1.1.1.1/help 这个页面验证：看到 “Using DNS over HTTPS: Yes” 就是成功了
  4. 安卓手机想全局生效：去系统设置的“私人 DNS”里填 one.one.one.one
  5. iPhone：装对应 App（如 1.1.1.1 App）来实现全局加密 DNS
