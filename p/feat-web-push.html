Web 推送通知

关掉网页，消息还能弹出来
👀 日常场景

关掉购物网站去干别的事，手机突然弹出一条通知：“您收藏的商品降价了！”网页明明关了，消息却还能找到你——这不是 App 的专利，浏览器网页也能做到，靠的就是 Web 推送。

原理：它是怎么运作的

💡 网站向浏览器推送服务订阅，拿到订阅地址后，服务端随时经推送服务把消息推到设备，由 Service Worker 弹出通知。

先看全过程

  1. 请求用户授权通知权限
  2. Service Worker 注册并订阅
  3. 生成 VAPID 密钥标识身份
  4. 订阅信息发给服务端保存
  5. 服务端经推送服务发消息
  6. SW 收到后弹出系统通知

它和“实时推送”名字像，但完全是两回事：实时推送要求网页开着，Web 推送网页关了也能收到。魔法在 Service Worker（SW，浏览器在后台跑的独立脚本，页面关了它还在）身上。首先网站向用户申请通知权限（Notification.requestPermission），用户点了“允许”；然后 SW 用 PushManager 生成一个订阅（subscription），包含推送服务的 endpoint 地址和加密密钥，发给自家服务器存好；之后服务器想推消息时，把内容加密发到 endpoint（Chrome 走的是 Google 的 FCM 推送服务），推送服务再下发到设备，SW 被唤醒，调 registration.showNotification 弹出通知。为什么需要 VAPID 密钥？它是网站的“身份证”（自愿应用服务器标识），防止别人冒充你的网站给用户推消息。点击通知一般要跳到对应页面，靠监听 SW 里的 notificationclick 事件。限制也有：iOS 直到近年才跟进支持且限制较多；用户一旦在浏览器设置里关了通知权限，网站无法再次弹窗，只能引导用户手动去开。

该允许网站发通知吗

  • 允许：适合“等不起”的消息：降价提醒、物流动态、抢票结果——这类“错过就亏”的消息，允许推送很值。
  • 拒绝：营销号一律拒绝：“点我领券”“限时秒杀”这种，允许一次就会被轰炸。第一次弹窗直接点“拒绝”。
  • 随时可反悔：允许了也能关：浏览器设置 → 隐私和安全 → 网站设置 → 通知，找到它关掉就行。
  1. 网站第一次弹窗问你要通知权限
  2. 想清楚：是“等不起”的消息就允许，是营销就拒绝
  3. 点了允许：关掉网页，降价消息还能推到你手机上
  4. 被轰炸了：去浏览器设置 → 网站权限 → 通知里关掉它
