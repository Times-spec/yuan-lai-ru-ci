分流规则：流量听谁的

从上往下，第一条命中的说了算
👀 日常场景

你想让 github.com 走代理，于是在规则里加了一行，保存重启，却发现没生效——或者更惨，之前好好的网站突然打不开了。十有八九，问题不在规则本身，而在规则的“顺序”上。

原理：它是怎么运作的

💡 规则是“条件→动作”的列表，按从上到下逐条匹配，第一条命中即停止；MATCH 是永远命中的兜底，必须放在最后。

先看全过程

  1. 一条新连接到达 Clash
  2. 从第一条规则开始逐条比对
  3. DOMAIN-SUFFIX 按域名后缀匹配
  4. IP-CIDR / GEOIP 按地址匹配
  5. 命中则执行 DIRECT / PROXY / REJECT
  6. 都没命中，落到最后的 MATCH

先认识规则类型。DOMAIN 是精确匹配（DOMAIN,example.com 只匹配它自己）；DOMAIN-SUFFIX 是后缀匹配，连所有子域一起命中，最常用；DOMAIN-KEYWORD 是域名里包含关键词就命中；IP-CIDR 按网段匹配；GEOIP 按 IP 归属国家匹配（GEOIP,CN 是国内直连的经典写法）；PROCESS-NAME 按进程名匹配（比如让某个游戏走直连）；MATCH 是“以上都不中就归我”的兜底。

每条规则的格式是“类型,参数,策略”，策略可以是 DIRECT（直连）、PROXY（默认代理）、REJECT（拒绝），也可以是一个策略组的名字。IP 类规则还有个小尾巴 no-resolve：默认情况下，遇到 IP 类规则 Clash 会先把域名解析成 IP 再比对，加上 no-resolve 就跳过这步——在 Fake-IP 模式下很有用。

规则一多，自己维护就很累，于是有了 rule-providers（规则集）：别人维护好的大型规则列表，你订阅它，Clash 定期自动更新，配置里只用一行 RULE-SET 引用。

最后是铁律：顺序即正义。Clash 从上往下扫，命中第一条就停，后面的看都不看。所以精确的、小范围的规则放前面，宽泛的（如 GEOIP,CN）放中间，MATCH 永远钉在最后。MATCH 放错位置，后面的规则就全成了摆设。

分流规则怎么写

  • 抄现成规则集（推荐）：RULE-SET 引用别人维护好的规则，自动更新
  • 手写几条：DOMAIN-SUFFIX、GEOIP 自己写，完全掌控
  • 套公开模板：社区沉淀的完整配置，拿来改
  1. 先想清楚：哪些走代理、哪些直连、默认走哪边
  2. 新手直接上 RULE-SET：在配置里引用现成的规则集订阅
  3. 只想加几条自己的：用 DOMAIN-SUFFIX 写，精确的放前面
  4. 记住铁律：精确的在前、宽泛的在后，MATCH 永远钉在最后
  5. 改完去“连接”面板看实际走向，对不上就调顺序
  6. 定期更新规则集订阅，域名世界天天在变
