邮箱验证码/魔法链接

点一下邮件里的链接，直接登录不用输密码
👀 日常场景

注册时填完邮箱，收到一封“点击此链接完成验证”的邮件；有些网站甚至没有密码框，输入邮箱后点邮件里的链接就直接登录了。你好奇过：一个链接，是怎么代替密码的？更神奇的是，这个链接点过一次就失效了。

原理：它是怎么运作的

💡 与短信验证码同构，只是通道换成邮件；魔法链接把一次性 token 藏进 URL。

先看全过程

  1. 用户输入邮箱地址
  2. 服务端生成一次性 token 并绑定邮箱
  3. token 设 10-30 分钟过期
  4. 经 SMTP 把含 token 的链接发到邮箱
  5. 用户点击链接回跳到网站
  6. 后端校验 token 有效即登录，用后作废

邮箱验证码和短信验证码是“同构”的——同样的生成、绑定、过期、核销逻辑，只是下发通道从短信网关换成了 SMTP 邮件。魔法链接（Magic Link）是它的优雅变体：不再让用户手动输入 6 位数字，而是把一次性 token 直接嵌进 URL（比如 https://site.com/auth?token=abc123），用户点一下就完成验证，体验上“无密码登录”。安全设计上 token 必须满足三点：高熵随机（猜不出来）、一次性（用后即焚）、短有效期（通常 10–30 分钟）。和短信相比，邮件通道的优势是成本几乎为零、全球可达；劣势是送达不可靠（进垃圾箱、延迟），且邮箱本身也可能被盗——所以魔法链接通常只用于登录，不用于支付这类高风险操作。另外注意：token 放在 URL 里会被浏览器历史、代理日志记录，所以有效期一定要短、用完立即作废。

网站该如何接入

  • Resend / SendGrid：开发者体验最好的邮件 API，模板和送达率成熟。
  • Amazon SES：AWS 的邮件服务，量大时成本极低。
  • Mailgun：老牌邮件 API，验证邮件场景常用。
  • Auth0 / Supabase Auth：认证服务内置邮件 OTP/魔法链接，开箱即用。
  1. 配置发件域名（SPF/DKIM/DMARC 三条 DNS 记录），否则邮件大概率进垃圾箱。
  2. 用户提交邮箱后，后端生成高熵随机 token，存入 Redis 并绑定邮箱、设 15 分钟过期。
  3. 调用邮件服务商 API 发送验证邮件，正文放上含 token 的链接。
  4. 用户点击链接回跳，后端取出 token 比对邮箱和有效期。
  5. 校验通过即建立登录会话，同时删除该 token 防重放。
  6. 同样要做发送限流，防止接口被用来轰炸别人的邮箱。
