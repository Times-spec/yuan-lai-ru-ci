SVG 矢量图

放大一百倍，依然清晰锐利
👀 日常场景

手机 App 的图标在高清屏上依然锐利，网站 logo 从 16px 的小图标放到首页大横幅都不模糊——它们大多是 SVG。而你拍的照片放大就全是马赛克。同是图片，“放大不糊”和“放大成马赛克”的分界线，就在“矢量”和“位图”之间。

原理：它是怎么运作的

💡 PNG/JPG 是像素点阵（位图），放大只能拉伸像素；SVG 是用数学公式描述图形（矢量），渲染时实时计算，任意缩放都不失真。

先看全过程

  1. 位图：把画面切成几百万个小格子存颜色
  2. 放大位图：格子被拉大，边缘出现马赛克
  3. 矢量：只记录“画圆心在哪半径多少的圆”
  4. 渲染时按当前尺寸实时计算每个像素
  5. 尺寸翻 100 倍：公式不变，重算一遍即可
  6. 结果：任意缩放，边缘永远锐利

位图（PNG/JPG/WebP）是“数像素”的：1000×1000 的图就是 100 万个颜色点。放大时信息量不会增加，只能把已有的像素拉大，所以糊成马赛克。JPG 还为了体积对颜色做有损压缩，文字边缘容易出现“毛边”。

SVG（Scalable Vector Graphics）反其道而行：它根本不存像素，存的是“画图指令”——一个圆就是一段带圆心半径的标签，一条曲线就是一段贝塞尔路径。浏览器渲染时按当前显示尺寸实时计算，所以 16px 和 1600px 用的是同一份文件，边缘永远锐利。而且 SVG 本质是 XML 文本：体积小、可直接内联进 HTML、能用 CSS 改颜色、能用 JS 做动画（图标 hover 变色、数据可视化、加载动画全是这个路数）。

边界也很清楚：照片这种色彩连续、细节随机的内容，用数学公式描述反而比存像素更占地方——所以照片永远是 JPG/WebP 的地盘。记住：几何形状、图标、logo、图表用 SVG；照片、复杂渐变用位图。

开发者：应该如何接入

  • 内联 SVG：把 SVG 代码直接写进 HTML，CSS/JS 可随意控制
  • SVG Sprites：多个图标合并成一个文件，用 use 标签按需引用
  • D3.js / ECharts：数据可视化库用 SVG 画图表
  1. 判断素材类型：图标/logo/简单插画才适合转 SVG
  2. 用 Figma/Illustrator 导出 SVG，或找设计师要矢量源文件
  3. 用 SVGO 等工具压缩，删掉编辑器塞的冗余信息
  4. 图标场景：内联或做成 sprite，保证可跟随文字换色
  5. 上线前检查：在普通屏和高清屏、浅色深色模式下各看一眼
